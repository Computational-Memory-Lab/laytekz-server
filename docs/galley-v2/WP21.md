# WP21 math-pdf-crop

## Summary
After a typeset, hovering a display formula (`\[…\]`, `$$…$$`, `equation`,
`align`, `gather`, … in the source) shows the typeset PDF's own pixels,
cropped at the formula's SyncTeX boxes, equation numbers included, captioned
"As typeset" (`data-tier="pdf"`). The crop is shown only when the formula is
provably the one typeset: the server's hash of the text it typeset matches
the editor's, every edit since is mapped (lines added above keep the crop),
and the SyncTeX file's `x-synctex-run` header names the run whose PDF is on
screen. An edit inside the formula falls back to KaTeX captioned "Preview:
changed since the last typeset"; any other doubt leaves KaTeX's drawing as
WP13 made it. The switch is `mathPreview.pdf` (on by default, still hidden on
the settings page until R1 lands). Nothing changes the document; there is
nothing to undo, and collaborators see nothing.

## Deviations
- **The compiled-text field is added to the editor by the layer itself** (`StateEffect.appendConfig.of(compiledField)`, once per view, outside any update: on `compileRequested`, on `compileFinished`, or at the first hover). WP13's `extension()` is not WP21's to change, and appended config survives the feature host's compartment reconfigures. Edits before the field exists are not needed: adoption checks the hash of the text at that moment.
- **Inline formulas are not cropped** (the plan's "inline crops only if the fixture tests pass": not attempted in this pass). Only `kind` `display`/`env` with `display: true` (not `\begin{math}`, not selections) get the PDF layer.
- **The SyncTeX route sends the file named by the run** (`lastSynctexPath`), not one derived from the current `rootFile`: a root changed since the run would otherwise send a stale file under a fresh header. It answers 409 while a typeset of the branch runs, and again if one started or finished during the read. Header `x-synctex-path` (URI-encoded) gives the client the root folder that the SyncTeX inputs are relative to.
- **How the crop is found** (no `synctex view` process; parsed in a module worker, in-thread where workers are missing): the character records (`x`, `$`) on the formula's lines are climbed to the outermost hbox whose characters all come from those lines. The opening line of a formula on several lines is left out (the paragraph before is broken there and its last line is recorded on it); the closing line is left out when text other than a comment follows the closing delimiter, and a one-line formula with text around it gets no crop. On one source line, boxes spanning the full line (a paragraph line or an alignment row) are dropped, and only such boxes means no crop. A crop taller than 48 pt per line plus two, on a rotated page, or on a page whose crop box is moved off the corner is refused. A run with a TeX error on the formula's lines is never cropped. Over several pages, the page with most of the formula is shown, captioned "As typeset (continues on the next page)".
- **When the PDF pane is hidden** (editor-only layout, phone), the layer loads the run's PDF itself through `util/pdfjs` (one document, replaced per run, destroyed when the page closes). When the pane shows a different run's PDF, there is no crop.
- The report's "Preview: typeset to see it exactly" and "not in the last typeset" captions are not built (outside the plan's acceptance).

## Privacy notes
- The client fetches `GET /api/projects/:id/output/synctex` from the same server, on the first hover after each typeset. The SyncTeX file holds the compile directory's absolute paths and the TeX Live install paths (already downloadable through `/output?path=….synctex.gz` in V1). Same access rule as the PDF: anyone who may open the project, bearer tokens included.
- Compile results now carry 16-hex-digit hashes of the open files' text; every reader of a compile result can already read those files.
- Nothing is stored; nothing leaves the server for another host.
