# WP27 wordcount-ui

## Summary
The rule-based word count (feature 13) in the app. The count in the preview's header (in the editor's header when only the editor shows) counts the main text by default, live while typing, and reads `3,412 words`, `3,412 / 4,000 words` (in the warning colour when over the target) or `214 of 3,412 words` with a selection. Clicking it opens a breakdown: parts, kinds and sections with their counts, why a part was found, characters and reading time, and Copy breakdown. Its checkboxes, the preset menu and each section's "Count as…" menu change the project's rule, so co-authors see the same count. Settings → Word count holds "Word count in the header" (this browser, on by default), the project's rule editor and the account's default rule. Three palette commands insert `%WC:` markers, each one undo step. This replaces WP06's interim word count.

## Deviations
- **The splice is per file, not per paragraph.** The open file is re-scanned whole from the state the server recorded where the document includes it (about 1 ms for a chapter, 10 ms for a 400 KB thesis), after a 300 ms pause (1 s above 512 KB). The briefing's "splice only the changed paragraph" would need the engine to restart mid-file, which it cannot do without changes to WP24's twin; the whole-file re-scan is fast enough.
- **A file that includes other files is never spliced**: after an edit the server is asked again (1 s after typing stops), because `countText` follows no includes and a child's effect on what follows is the server's to work out. Leaf files (chapters, sections) and single-file documents are live. An edit that changes what follows a file (typing `\appendix`, a new `\newcommand`) also asks the server again.
- **The account default** is a separate row, `wordcount.accountRule` (account scope, value always null), whose control reads and writes the account preference `wordcount.rule` itself through `/api/account/preferences`. The registry cannot hold two settings with the id `wordcount.rule`, and the project setting must keep that id (it is the server's `ext` key), while the server reads the account preference of the same name.
- **The pdf.status item hides in the Editor-only layout** and the editor.status item shows only there, so the page never has two `word-count` test ids.
- **References and Not counted** are shown as rows without a working checkbox: the engine never counts references, and "Not counted" is what a section override or a `%WC:excluded` marker produces.
- **The "Other documents" and "Not followed" lists** are one line each in the popover, and the "Unreachable files" list is not shown.
- **No "Characters" per part**: the popover shows the counted characters, with and without spaces, and the reading time.
