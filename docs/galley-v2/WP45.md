# WP45 web-readiness

## Summary
The website now behaves like a product behind Cloudflare: hashed assets are
cached for a year, the app page and plugin files are revalidated on every
load, a missing file (an old lazy chunk, `favicon.ico`) is a JSON 404 instead
of the app page, every response carries `nosniff`, a referrer policy, a
permissions policy and `X-Robots-Tag`, and the app page carries a
report-only CSP that hashes its inline scripts. The page has real icons, a
web manifest (install as an app), description and `og:` tags, a `<noscript>`
line, and a notice on browsers too old for the app ("Continue anyway" mounts
it). After a deploy, open tabs get one "Laytekz was updated. Reload to get the
new version." toast (setting: Appearance > "Say when Laytekz has been
updated"). New public pages: `/about` and `/.well-known/security.txt`. The
waiting-for-approval page now names the address, the contact or the email to
expect, and what to do next (with desktop-app wording after a desktop
sign-in). Cloudflare's 520 to 530 answers read "The server is not responding."
(a 524 on a typeset names the 100-second limit). The sign-in card gains an
About link and, when the server names one, a desktop download link.
Administrators see an "N waiting" chip (`admin-waiting`) in the project
list's toolbar (`home.toolbar` slot) while accounts wait for approval; it
opens /admin.

Not built (left for later): ⌘P printing the PDF, the notify webhook
(`srv/notify.ts`), the CSP report endpoint (`/api/csp-report`; the policy is
report-only without a `report-uri`), invitation auto-approval, and the
deploy-side items (R2, R3; `verify-edge.sh`, off-machine backups, uptime
alerts).

## Deviations
- **The build revision is WP03's `buildRev()`** (a hash of the served `index.html`), not `ALDINE_BUILD_REV`: it changes with every build and needs no deploy change. The page carries it as `<meta name="laytekz-rev">`; the client compares it with `rev` from `/api/capabilities` (WP03 already answers it). The webShell feature does not replace the `rev` capability. `/api/health` is unchanged.
- **The desktop link comes from the `desktopUrl` capability** (webShell server feature, public), not from a `galley-desktop` meta tag and `desktop-link.ts`/`desktopLink.ts` as the report proposed.
- **`/about` is registered by the webShell server feature,** with its own copy of the sign-in pages' shell (`pages.ts`), because `authPage` is a closure inside `registerRoutes` and WP45 may change only the approval copy there.
- **`/index.html` and other `.html` names still get the app page** (base-path.test.mjs expects it); the static-miss check decodes and collapses dot segments first, as the static plugin's `allowedPath` does.
- **No `<script nomodule>`:** the classic browser check already runs in browsers too old for modules and shows the notice.
- **The reload toast** is checked when the tab becomes visible (at most once a minute), when the network comes back, and every ten minutes while visible; not "after each collaboration reconnect" (no hook reaches a feature's `boot`), the `online` event stands in for it. It shows once per new revision per tab and never reloads by itself; Reload goes through the browser's unload, so the editor's unsaved-edits guard still asks.

## Privacy notes
Nothing new leaves the browser: the version check is a same-origin `GET /api/capabilities` (already made at load). The report-only CSP sends no reports (no `report-uri`; violations appear only in the browser console). `security.txt` repeats the support contact the privacy page already shows, and is 404 without one. `X-Robots-Tag: noindex, nofollow` is now on every response, so search engines index none of the server's pages (robots.txt stays Cloudflare's, open, so crawlers can read the tag).

## Operator variables
- `GALLEY_DESKTOP_URL` (unset by default): an https URL for the desktop app's download (releases page). Shown on the sign-in card (labelled per platform, hidden inside the desktop app) and on `/about`. A non-https value is ignored.
- `ALDINE_PUBLIC_URL` (existing) now also makes the app page's `og:url` and `og:image` absolute, puts `Canonical:` in `security.txt` and the websocket origin in the report-only CSP.

## For later packages
- A route that wants its own caching sets `cache-control` itself: the `onSend` hook only fills it for `/assets`, `/cmaps`, `/plugins` and the shell files, and only when unset (or the static plugin's `public, max-age=0`). The base headers are likewise only added when a route has not set them.
- A new inline `<script>` in `index.html` is hashed automatically at start-up; nothing to update.
- `isStaticMiss` treats any not-found path whose last segment has an extension (other than `.html`) as a file: an SPA route must never end in `.<ext>`.
