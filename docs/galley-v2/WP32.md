# WP32 highlight-data

## Summary
The highlighter's shared data layer works end to end: highlights live in a
`highlights` side map of each file's Yjs doc, anchored by Yjs relative
positions (start assoc 0, end assoc −1), drawn as translucent marks in Source
and Visual mode, synced live to co-authors, kept across reloads, undone and
redone with the editor's own Mod+Z (also after the highlighted text was
deleted and restored, for every peer), and never written into the file. A
person can use it now through ⇧⌘H ("Highlight the selection", a toggle) and
palette commands; the master switch is Settings → Highlighter → Highlighter.
WP37 adds the button, card, right-click entry, colour dialog and list.

## Deviations
- **⇧⌘H and palette commands are in WP32**, so the feature is usable before WP37: keybinding `highlighter.highlight` (page-capture, ⇧⌘H, changeable) running command `highlighter.highlight` (toggle: paints the selection with the default colour, or removes it when the selection already shows exactly that colour), `highlighter.highlight.<preset>` ×6, `highlighter.remove`, `highlighter.clearMine`, `highlighter.clearAll` (confirmation). All refused to viewers and showcases, listed only while the setting is on. WP37 keeps or reshapes them in its own directory.
- **Settings are account scope** (device-mirrored as `aldine.highlighter.*`, so they work without accounts), not the analyst's per-browser key: `highlighter.enabled` (true, palette toggle), `highlighter.showOthers` (true), `highlighter.color` (`'yellow'`, presets only), `highlighter.strength` (`'medium'`). The rest of the analyst's settings (remember last colour, menu, card, paste memory, colour-blind patterns, custom colours) are WP37's.
- **`files: /./`**: the highlighter runs in every file the code editor opens (`.bib` and others too), not only `.tex`.
- **Author ids:** `acct:<userId>` when the editor has a user id, else a per-browser `anon:<random>` kept in `localStorage['aldine.highlighter.me']`.
- **Stored colours:** an unknown colour value is kept as stored when a highlight is trimmed by someone else, and drawn yellow; only presets and `#rrggbb` reach a style.
- **Remote text changes** re-resolve the drawn ranges from the anchors 150 ms after they arrive (CodeMirror mapping in between); any change to the map re-resolves at once.
- **GET `/api/projects/:id/highlights`** has no hash cache yet: each call reads the loaded docs and the snapshots of the branch's other text files (a lagging snapshot is brought up to the file's LF text in a scratch doc). Fine for normal projects; a cache keyed by the file hashes can come later if the list is slow.
- **Tidy on load** removes junk, malformed v1 entries and collapsed ones (all their text gone), keeps entries of a newer version, and keeps the newest 5,000 (logged when it removes anything).

## Privacy notes
- Each highlight stores the author's display name and id (`acct:<id>` or a random per-browser id) and a time, in the file's Yjs snapshot under `META_DIR/yjs` and in every connected browser's copy of the doc. Everyone who can open the project (viewers and link visitors included) can read them through the doc and through `GET …/highlights`. They never reach the file on disk, git, the compiler, the PDF or the ZIP download.
- When WP28 wires `moveDocState`/`copyDocState`, highlights follow renames, new branches and project copies (a copy's new owner sees the original authors' names on them).
- `localStorage['aldine.highlighter.me']`: the random author id of a browser without accounts. No outbound hosts.

## For later packages
- **WP37:** import everything through `features/highlighter/api.ts`: `toggleSelection(view, colour)`, `applyHighlight(view, ranges, op)` (returns `'done' | 'unchanged' | 'off' | 'readonly' | 'empty' | 'blank' | 'full'`), `clearHighlights(view, 'mine' | 'all')`, `highlightRuns(state)` (all resolved runs), `shownRuns(runs, cfg)`, `flatten`, `isPainted`, `normalizeHex`, `colorName`, `PRESETS`, `hlConfig` (the view's config: ydoc, undo manager, `me()`, `showOthers`, `canWrite()`), `fetchProjectHighlights(projectId, branch)`. Marks are `.cm-hl.cm-hl--<preset|custom>` with `data-hl` (key), `data-hl-color` and `title` ("Yellow highlight by Ada"); custom colours set `--hl`. The editor root carries `data-hl-strength`. Theme colours are in `highlighter.css` (imported by `extension.ts`).
- Writes always go through `ydoc.transact(…, HL_ORIGIN)` between `stopCapturing()` calls; never write the map with another origin from a person's action, or Mod+Z will not take it back.
- **WP28:** nothing to do for highlights beyond the planned `moveDocState`/`copyDocState` calls: the map rides in the snapshot.
