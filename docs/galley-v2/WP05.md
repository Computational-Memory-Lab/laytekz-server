# WP05 editor-host

## Summary
The code editor now hosts feature modules: each feature's `editor`
contribution runs in a compartment of its own (outside the mode compartment,
reconfigured on a mode or setting change, never remounted), with its key
chains, mod-click handlers, automatic-edit rules, completion sources and
filters, and `afterFormat`; the input core (key chains, mod-click, the
editor's keybindings, the context menu) is installed once. CodePane's
language, brackets and completion list moved to `editor/core/*` unchanged,
and the editor's own settings (gutters, active line, whitespace, indent,
wrap, completion list) exist as registry definitions whose defaults are the
V1 editor. PdfPane has `pdf()`, `textSelection()`, selection reports and the
PDF app menu (README D2). Visual mode's widget clicks yield to mod-clicks, and
the late-bound hooks (citation command, moved files) are implemented. For a
user nothing changes in wave 0: without a `featureHost` prop no feature runs,
the settings' defaults are V1's, and the context menu installs only once some
feature has menu entries.

## Deviations
- **Several compartments, not one `settingsComp`.** `EditorSettingsSlots` keeps one compartment per place V1 had each extension (line numbers, active-line gutter, whitespace, fold gutter, active line, wrapping, indent unit, and the Source content's wrapped-line indent). One compartment would have moved the diff gutter after the fold gutter and changed the extension order.
- **Editor setting ids and defaults** (pure data, `EDITOR_SETTINGS`, account scope): `editor.lineNumbers` (true), `editor.activeLine` (true), `editor.foldGutter` (true), `editor.whitespace` (false), `editor.wrap` (true, Source only: Visual always wraps), `editor.wrapIndent` (true, dependsOn wrap), `editor.indent` (`'detect' | '2' | '4' | 'tab'`, default **`'2'`**), `editor.completion` (`'typing' | 'request' | 'off'`, default `'typing'`, section `completion`, label "Show completions"; the plan's "suggestions", renamed so it is not confused with feature 12's inline suggestions). The settings report proposed "Detect" as the indent default; that would change Tab and Format document for files indented otherwise, so the default is V1's two spaces and WP23 may flip it. `'2'` installs no `indentUnit` (CodeMirror's own two spaces, exactly V1). No row is `palette: true` yet (WP23 decides).
- **The context menu installs only when some enabled module has `contextMenu` entries.** WP04's menu opens inside an existing selection even without entries; installing it with none would replace the native menu for every user in wave 0. With the probe, or from wave 1 when a feature adds entries, it installs.
- **Key chains replace V1's Tab keys only when `keyChainsExtension()` starts.** If it throws (WP04 not built), the V1 `Tab → acceptCompletion` keymap and `indentWithTab` stay. With chains, the main keymap keeps a `Shift-Tab → indentLess` fallback (WP04's chain has Shift-Tab outdent at 0 too, so it is never reached; it only guards a chain without one).
- **The editor keybinding dispatcher** (`editorKeybindingHandler`) is one `Prec.highest` keydown handler placed after Vim (Vim, also highest and earlier, sees keys first). It runs `bindingFor(e, ['editor'], { desktop })` and, for a **feature's** binding (an id with a `<featureId>.` prefix), its command through `featureHost.runCommand`; true stops the key. Core editor bindings pass to the extension that defines them: WP04's `follow` (Alt+Enter) is run by its mod-click plugin, which declines where there is nothing to follow, so the key keeps its V1 meaning there. A registry that throws turns the dispatcher off for that editor, once.
- **`featureHost` is read when a file opens** (the view is built per file): a changed `modules` list applies at the next file. The context's `notify`, `openSettings`, `runCommand`, `page()` and `identity.id` read the prop live.
- **`EditorFeatureCtx.readOnly()`** is `view.state.readOnly`: true before the view exists and until the first sync (the load gate), as the editor itself is.
- **`extension(ctx)` is called again** on every mode change and on a change of one of its `deps`; module-level StateFields and Facets keep their identity, a field created inside `extension()` starts afresh.
- **Completion:** every source's result (core and feature) passes the running features' filters in manifest order; a filter that throws is skipped. Feature sources are made from the context when the feature's compartment is built.
- **`afterFormat`** specs are dispatched one after the other (each on the text the previous left), `userEvent 'input.format'`, between the same two `stopCapturing()` calls as the formatter's changes, so one Undo takes back all of it. Format document returns `'formatted'` when only a feature changed the text.
- **`onFilesMoved`** keeps the frozen signature and delegates to `applyFilesMoved(projectId, branch, moves, targets)` (exported for tests). It copies a moved file's spot to the new doc name (unless the new name has one) and closes the parked docs of moved files (never renamed: a parked doc's connection is to the old name, and the moved file loads afresh from the server, never reseeded). The spot store cannot be listed, so a folder's move carries the spots of the paths in `moves` and of the parked docs under the folder; a `rename`/listing API in `editor/fileSpots.ts` (WP29's in wave 3) would carry the rest.
- **`citeCommandFor`** asks the most recently set resolver first; an answer that is not a command name (`/^[A-Za-z@]+\*?$/`, a leading backslash dropped) is skipped. insertCitation rewrites only a new `\cite{key}` (`citeInsert.ts` untouched).
- **PDF app menu policy details (D2):** "inside a PDF text selection" means the right-click lands within the client boxes of the selection read at the button-2 press (a Mac's Control-click counts), before the browser can change it. Shift, a touch press, no feature host, no entries, or no entry with items keep the native menu. Shift+F10 and the Menu key open it at the selection's first box (`PdfMenuTarget.point` null); a `contextmenu` event those keys also send within 600 ms is cancelled so the native menu does not follow. Groups run annotate, navigate, copy, separated; Copy (test id `pdf-context-copy`) ends it and writes the selection's text through the async clipboard, falling back to `execCommand('copy')`.
- **`textSelection()`** reports the page the selection starts on, its text there (text nodes only, `\0` removed) and one box per line in PDF points (top-left origin), clamped to the page; `pdfUrl` is the link of the document on screen. Selection reports (`onTextSelection`) fire 150 ms after the selection settles, only on change, and null once it goes (and on unmount).
- **`pdf.status`/`pdf.actions`/`pdf.overlay` are rendered by WP06** (README D3); PdfPane adds no overlay host. A feature that draws over the pages finds them through the DOM (`canvas[data-page]` in `[data-testid=pdf-pane]`) until a later request adds an API.
- **Additional exports** (no contract changed): `featureHost.ts`: `EditorFeatureHost`, `createEditorFeatureCtx`, `FeatureCtxSource`, `runsIn`, `runsInMode`, `DEFAULT_FEATURE_FILES`, `editorKeybindingHandler`, `pdfMenuEntries`, `pdfContextMenuItems`, `PDF_MENU_GROUPS`, `pointInRects`, `mergeLineRects`, `toPdfRect`. `completion.ts`: `coreCompletionSources`, `filteredSource`, `completionExtension`, `CompletionSlot`, `CompletionFilter`, `CompletionParts`. `editorSettings.ts`: `readSetting`, `watchSettings`, `readEditorSettings`, `EditorSettingValues`, `EDITOR_SETTING_ID_LIST`, `detectIndent`, `indentUnitFor`, `EditorSettingsSlots`. `editorSettingDefs.ts`: `EDITOR_SETTING_IDS`, `IndentChoice`, `INDENT_CHOICES`, `CompletionActivation`, `COMPLETION_ACTIVATIONS`. `language.ts`: `LATEX_LANGUAGE_OPTIONS`, `latexHighlighting`, `latexLanguage`, `packageCompletionSource` (and re-exports `aldineLatex`, `aldineHighlight`, `latexCompletionSource`). `brackets.ts`: `bracketExtensions`, `beginBraceExtensions`, `bracketKeymap`. `hooks.ts`: `applyFilesMoved`, `MoveTargets`, `movedPath`, `docNameOf`. `visual/history.ts`: `undoBoundaryFrom`, `closeUndoStep`.
- **`visual/index.ts` asks the `modClick` facet itself** (any handler with a target at `posAtCoords`, the modifier as WP04's `modClickHeld`). WP04's working copy exports `modClickTargetAt`/`isModClick` for this; they are not in the committed contract, so the scratch tree could not use them. The integrator may switch `modClickWanted` to them.

## Privacy notes
- The editor settings are account scope: when the account syncs preferences (WP02), the chosen gutter, wrap, indent and completion values are stored with the account on the server. Nothing else leaves the browser.
- The PDF app menu's Copy writes the selected text to the clipboard on the person's click only. No host is contacted.

## For later packages
- **A feature's editor contribution** (`features/<id>/index.ts`): fill `editor` and the host does the rest; nothing in CodePane changes.
  ```ts
  editor: { deps: ['links.underline'], extension: (ctx) => linkMarks(ctx.setting<boolean>('links.underline')),
    modClick: [{ id: 'links.url', priority: 50, target: urlAt, run: openUrl }],
    keyChains: [{ key: 'Tab', priority: KEY_CHAIN_PRIORITY.Tab.closerStepOut, id: 'pairs.stepOut', run: stepOut }] },
  ```
  `files` (default `/\.(tex|ltx)$/i`) is fixed per open file; `modes` (default both) and `deps` reconfigure only that feature's compartment. Define StateFields at module level. `completionSources` are made from the context; `completionFilter` sees every source's result. `afterFormat(state)` returns a ChangeSpec on the formatted text, or null.
- **The citation command** (WP19): in `activate(page)`, `return setCiteCommandResolver((state, path) => commandFor(path) /* 'parencite' */);`.
- **Moved files** (WP28/WP29): Editor.tsx already calls `onFilesMoved(projectId, branch, moves)` for every `filesMoved` event (WP06).
- **The PDF menu** (feature 19): `pdfContextMenu: [{ id: 'pdfComments.add', group: 'annotate', order: 10, items: (t) => (t.selection ? [{ id: 'pdf-comment', label: 'Comment on this text', onSelect: () => addComment(t.selection!) }] : null) }]`; the selection reaches features as `page.events.on('pdfSelection', …)` and `page.pdf()` gives `{ url, doc }`.
- **Core files later packages own:** WP12 (wave 1) owns `core/brackets.ts` and `core/completion.ts` (`coreCompletionSources` is the core list; `bracketExtensions`/`beginBraceExtensions` are placed where V1 had them, so keep their inner order). WP31 (wave 3) owns `core/language.ts` (`LATEX_LANGUAGE_OPTIONS.autoCloseTags`, `packageCompletionSource`). WP20 (wave 2) owns `editor/spellcheck.ts`; WP37 (wave 4) owns `visual/index.ts`. CodePane, PdfPane and `visual/history.ts` are integrator-only from wave 1.
- **Undo steps:** `closeUndoStep(view.state)` (or `state.facet(undoBoundary)()`) works in Source and Visual mode.
