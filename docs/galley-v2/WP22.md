# WP22 references-panel

## Summary
Feature 9's panel. The sidebar tab "References" (the `references` plugin) has
one box that searches papers or takes a DOI, arXiv ID, PubMed ID, ISBN, a
formatted citation or pasted BibTeX (the Google Scholar path). Choosing a
result opens a preview sheet in the panel: the exact entry (editable), an
editable key checked as you type, the `.bib` it goes to (or a new file),
"Cite at the cursor" and "Load … in the main file". Add writes the entry
through WP16's routes and cites it; the toast's Undo removes both. Results
carry badges (DOI, arXiv, PMID, Preprint, Published version available, In
project as …), failing sources show as chips, and free text gets an "Open in
Google Scholar ↗" link that the user's browser opens. The panel lists the
citations the last typeset left undefined, each with "Find online", which
searches for the paper and gives the new entry the key the text already
cites. In `\cite{…}` completion, a last item "Search online for “…”" opens the
panel with what was typed; nothing is looked up until it is chosen. Settings ›
References holds four per-person switches and the four project settings WP16
reads.

## Deviations
1. **Undo of the `\cite`** uses a range the editor maps through every change
   (`features/references/citeTrack.ts`, installed by the feature's editor
   extension in TeX files) instead of an `insertCitation` that returns a
   handle from CodePane: CodePane is integrator-only in wave 2. The host finds
   the citation's exact change by comparing the text before and after the
   existing `insertCitation` (synchronous), so WP19's command resolver still
   picks the command.
2. **The page reaches the plugin host through `bindPluginPage`**, called from
   the references feature's `activate(page)`, because `Editor.tsx`'s
   `pluginCtx` cannot change in wave 2. Without a bound page (feature off or
   failed) the host falls back to V1 behaviour: no Undo of the `\cite`,
   toasts without a button, `canEdit()` true (the server still refuses
   viewers).
3. **The query reaches the panel through the host** (`showPluginPanel`):
   `EditorPageCtx.ui.showPanel(id, query)` passes a query only to the search
   panel today.
4. **"Find missing citations"** is a block at the top of the panel (and two
   palette commands) rather than only an errors-list action: undefined
   citations are warnings, and the errors list shows plugin actions only
   when a typeset failed. The errors action is registered too.
5. **"Cite at the cursor after adding" is not marked `automatic`**: it is the
   default of a visible checkbox in the preview, part of an explicit Add.

## Privacy notes
- The browser contacts only the Laytekz server (`…/references/lookup`,
  `preview`, `insert`, `remove`, `targets`, `/bib`). The server's outbound
  calls are WP16's.
- The Google Scholar link is a plain `<a target="_blank" rel="noopener
  noreferrer">` to the URL the server builds (`https://scholar.google.com/…`
  only); Laytekz never fetches it.
- The completion item sends nothing: choosing it opens the panel.
- Nothing is stored; the settings are account preferences and project `ext`
  values like every other setting.
