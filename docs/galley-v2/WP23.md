# WP23 settings-complete

## Summary
The settings page is now complete for a user: a search field in the header
(rows and sections filter as you type, "4 settings match", Escape clears then
closes, `/` comes back to it), the sync status ("Saved to your account",
"Saving…", "You're offline…", "Settings stay on this browser"), a Reset link
on every row that differs from its default, "Reset this section", "Reset all
settings…", export and import of `laytekz-settings.json` with a preview, and
Undo for every reset and import in one step. The Keyboard shortcuts section
lists every keybinding the app and its features registered, grouped, each
with its keys, a recorder, None and Reset, then the keys that never change.
Editor text has a live typography preview in Source and Visual styles. The
Desktop app section opens the desktop app's own settings window, Labs has a
note, the phone nav follows the section in view, and the two V1 dialogs are
retired (no entry point opens them).

## Deviations
- **Search matching.** Rows match on label or keywords through `util/paletteRank`'s `matchScore`, keeping scores under 60 (words, word starts, word insides, all words of the query, whole keywords and keyword starts) and dropping the palette's scattered-letter match. "font" therefore finds Font, Font size and Font ligatures, and also Interface text size and Visual mode text size, whose keywords name fonts (the acceptance line "finds 3 rows" comes from the analyst's test, which only asks that those three are found). A section whose title matches shows whole; embedded blocks (account, connections, project, desktop) answer to fixed terms (`search.ts` `EMBEDDED_TERMS`) and show whole; the Shortcuts section filters its own bindings.
- **What reset, Reset all and export cover:** account- and device-scope settings shown on the page plus the shortcut overrides (`keys.shortcuts`). Never: project settings, `editor.mode` and `pdf.zoom` (toolbar state), `account.sync` (the switch that decides where settings live), names, connections, tokens. Project rows have no Reset link.
- **Import is additive.** It changes only the settings the file names (the preview says so); unknown ids and project ids are ignored and counted, invalid values skipped and counted, a file from a newer format version refused.
- **Undo restores exact bytes.** Values go back through `setSetting`/`resetSetting` (so other tabs and the account follow), then each device key gets back the exact text it held (a V1 key's `'0'`, a junk value nobody wrote), written directly; that text always decodes to the value just set. This is the one place outside the store that writes a device key.
- **Retiring the dialogs** is a comment, not a deletion: WP06 already sends every entry point to the page, `settings/types.ts` (frozen) needs `ProjectSettings`'s props, and deleting upstream code would only add merge conflicts.
- **Focus on open:** the search field on desktops; the panel on phones, so the keyboard does not cover the page.

## Privacy notes
No new host or route. Export builds the file in the browser and downloads it; import reads a file the person picks, in the browser. Neither sends anything anywhere. The file holds setting values only (no names, emails, tokens or project data).
