# WP35 library-server

## Summary
The server half of feature 8 (reference managers) now exists. Each editor of a
project can link their own library to a `.bib` file of their own (at most 5
links per project): Zotero (pasted key, or "Sign in with Zotero" once the
operator registers an app), Mendeley (OAuth, only once the operator registers
an app), or a `.bib` on their computer that the desktop app pushes. Zotero and
Mendeley links include subcollections by default, leave out abstracts, files
and tags by default, and sync in background jobs; a key renamed in the manager
is reported after a sync, and "update citations" rewrites the `.tex` files in
one commit. V1's single owner link (`meta.zotero`) shows as the link `zotero`
and keeps working through V1's code. The panel is WP36's; until it lands users
see nothing new (the V1 Zotero panel keeps working, spec 05 is green).

## Routes (all in `features/libraries/server.ts`)
Account connections (signed in when accounts are on; bearer tokens are refused
by the global guard on every non-project route):

| Route | Answer |
|---|---|
| `GET /api/libraries/:provider/connection` (`zotero`, `mendeley`) | `{provider, enabled, connected, name, oauth, keyPaste}` |
| `PUT /api/libraries/zotero/connection` `{apiKey}` | the same, after checking the key with Zotero (Mendeley: 400, it signs in) |
| `DELETE /api/libraries/:provider/connection` | `{ok}`; the person's links pause |
| `GET /api/libraries/:provider/libraries` | `{libraries: [{id, name, kind: 'user'\|'group'}]}`; Zotero ids `users/<n>`, `groups/<n>`; Mendeley `me`, `group:<id>` |
| `GET /api/libraries/:provider/collections?library=` | `{collections: [{id, name, parent, path}]}` (`path`: "Thesis / Chapter 2") |
| `GET /api/libraries/:provider/search?library=&q=&format=` | `{results: [{itemId, key, title, authors, year, bibtex}]}`, from the person's own library |
| `GET /api/libraries/:provider/connect?return=` | 302 to the provider's sign-in (404 until configured). `return`: `/p/<id>`, `/p/<id>/settings[/<section>]` or `/settings[/<section>]` |
| `GET /api/libraries/mendeley/callback`, `GET /api/libraries/zotero/oauth/callback` | 302 back to `return` with `?library=<provider>&connected=1`, or `&error=state\|denied\|failed` |

Project links (`linkId` matches `^[a-z0-9]{1,24}$`):

| Route | Who | Body | Answer |
|---|---|---|---|
| `GET /api/projects/:id/libraries` | anyone who can open the project | | `[{id, provider, linkedBy, linkedByName, mine, canChange, library, libraryName, collection, collectionName, bibFile, recursive, omitFields, lastSyncedAt, pausedReason?, legacy?}]` |
| `POST /api/projects/:id/libraries` | members who can edit (not link visitors) | `{provider, library?, collection?, recursive? (default true), bibFile?, omitFields?, branch?, replace?}` | `{link, jobId?}` (no job for `desktop-file`) |
| `PATCH /api/projects/:id/libraries/:linkId` | its linker or the owner | `{library?, collection? (null clears), recursive?, omitFields?, bibFile?, branch?, replace?}` | `{link, jobId?}` (a sync starts when anything changed) |
| `DELETE /api/projects/:id/libraries/:linkId` | its linker or the owner | | `{ok}`; the file stays, now editable |
| `POST /api/projects/:id/libraries/:linkId/sync` | members who can edit | `{branch?, force?, olderThan?}` | `{jobId}`; 409 `code:'paused'` with the sentence; 400 `code:'desktop'` |
| `GET /api/projects/:id/libraries/jobs/:jobId` | anyone who can open the project | | `{state: queued\|running\|done\|error, linkId, branch, result?: {synced, unchanged?, fresh?, itemCount?, bibFile, format}, renamedKeys?: [{from, to}], error?, code?}` |
| `PUT /api/projects/:id/libraries/:linkId/content` | the link's own linker | `{content, branch?}` (content at most 20 MB) | `{ok, synced, itemCount, bibFile, format}` |
| `POST /api/projects/:id/libraries/update-citations` | members who can edit | `{branch?, renames: [{from, to}]}` | `{ok, files, replaced}` |

- **Defaults.** File: `zotero.bib` / `mendeley.bib` / `library.bib` beside the
  root file, then `<provider>-<first name>.bib` when a link or an existing file
  has it. An explicit `bibFile` that another link writes is 409 `code:'taken'`;
  one that exists unlinked is 409 `code:'exists'` unless `replace: true`.
  `omitFields` groups: `abstract`, `files` (file, annote, annotation), `tags`
  (keywords, mendeley-tags), `extra` (note, extra); default the first three for
  Zotero and Mendeley, none for a desktop file.
- **First sync.** A link whose first sync fails is removed again (V1's rule: a
  library that cannot be exported never becomes the link); the job reports
  the error.
- **Jobs.** At most 2 run server-wide, one per link (a second press returns
  the running job's id); finished jobs are kept for an hour, in memory.
- **Pause.** `pausedReason` is computed on every read: the linker's account is
  gone or disabled, they are no longer a member, they disconnected the
  provider, or Mendeley is no longer configured ("Paused: Bob Member no longer
  has access. Link your own library or unlink."). A sync the provider refused
  (401/403) is remembered until a sync works.
- **Signal.** Every link change and every finished sync sets the branch signal
  key `libraries` (a new value each time): open editors refetch the links.
- **Writes.** Viewers, link-visitor non-members, showcases and bearer tokens
  cannot write any of these (no `tokenWrites`, no `viewerWrites`): linking and
  syncing use a person's own credentials, and the desktop push comes from a
  session (`sessionFetch`).

## Storage
- Link definitions: `ProjectMeta.ext['libraries.links']`, a project setting
  defined by this feature with `clientWritable: false`, `clientVisible: false`,
  `copyWithProject: false`. Each link holds ids, names, the file and the
  options, never a credential.
- Sync state: `META_DIR/links/<projectId>/<linkId>.json` (`lastSyncedAt`,
  version cursor, format, item id → key map, stored pause).
- Credentials: the account's `connections` rows, `zotero` (V1's row:
  `{apiKey, userID, username}`, pasted or from Zotero sign-in) and `mendeley`
  (`{accessToken, refreshToken, expiresAt, profileId, name}`; a rotated
  refresh token is saved before the new access token is used).

## Capabilities
`libraries: {zotero: {key: true, oauth}, mendeley, desktopFile: true, maxLinks: 5}`;
`oauth` and `mendeley` are false until the operator sets the variables below.

## Deviations
1. **The ext key is `libraries.links`, not `refs.links`.** WP03's host only
   accepts project setting ids `<featureId>.<name>`, and this feature is
   `libraries`.
2. **V1's link is read through, not migrated.** Its `meta.zotero` holds the
   owner's API key, which may not go into `ext` (the plan: no secrets in
   `ext`). It shows as the link `zotero` (`legacy: true`), V1's `syncProject`
   syncs it, and DELETE removes `meta.zotero`. A PATCH migrates it: the owner
   must have a connected Zotero account; the link gets a new id, runs on that
   connection, and `meta.zotero` (with the key) is deleted.
3. **A new link holds no key.** V1 copied the key into the project so the link
   survived the account forgetting it; a V2 link runs on its linker's current
   connection and pauses when they disconnect.
4. **No URL provider** (`providers/url.ts`): the plan lists URL links as not
   built. **No `providers/desktopFile.ts`**: a desktop link needs no provider
   code; `pushContent` in `link.ts` writes the pushed text.
5. **Mendeley syncs in full** each time (500 documents a page) rather than
   with `modified_since`/`deleted_since`: the file is rebuilt whole anyway,
   and an unchanged library writes nothing and commits nothing.
6. **Synced files carry no timestamp** in their header, so a sync that finds
   the same entries leaves the file and history untouched.
7. **`update-citations`** is a route of its own (not in the frozen list), at
   `POST /api/projects/:id/libraries/update-citations`, because the job only
   reports renames; WP36 calls it from the notice.

## Privacy notes
- Hosts contacted, only when a person connects, lists, searches or a sync
  runs: `api.zotero.org` (and `www.zotero.org/oauth` for Zotero sign-in, when
  configured); `api.mendeley.com` (API and OAuth, when configured). They
  receive the person's key or tokens and the library and collection asked for.
  Elsevier's Mendeley scope is `all` (read and write); the server only reads.
- Stored: see Storage. Tokens and keys never reach a browser (tests assert
  it). The OAuth state is random, kept in memory for 10 minutes and bound to
  the browser by an HttpOnly cookie signed under `subkey('library-oauth')`; a
  callback is accepted only for the account that started it.
- What collaborators see: the linked `.bib` (abstracts, files and annotations,
  and tags left out by default), the linker's display name and library and
  collection names in the link list. Search answers go only to the person who
  owns the library.
