# WP42 agent-label

## Summary
Edits an agent makes through MCP now carry the agent's own name. A request
that sends `X-Laytekz-Agent: codex` (the desktop app's ▶ Codex does, WP25)
commits as "Codex", shows as "Codex (for Ada)" in presence, records the
project's last edit as Codex's, lists in the review answer with
`agent: "Codex"`, and History names it Codex with the agent dot; Revert works
as for Claude. No header, or any name off the allowlist, is Claude as before.
The owner's addition: the commits the server writes for itself carry the
product's name (committer and anonymous author "Laytekz <laytekz@localhost>",
subjects "laytekz: autosave" and so on, a named person without an email
"…@laytekz.local"), while everything that reads history knows both the old
("Aldine", "aldine:", "…@aldine.local") and the new forms.
The toast "Codex edited 1 file" needs request R2 (Editor.tsx, integrator only).

## How it works
- The label is a property of the MCP request, not of the token: `mcp/server.ts` runs the request inside an AsyncLocalStorage scope, and the write path reads `currentAgentAuthor()` where the request writes (`commitAgentWrite`, `markAgentPresence`, `noteEdit(AGENT_EDITOR)`), so `mcp/tools.ts` needed no change. It is read only where the request writes, never in a timer (a timer keeps the scope of whichever request armed it); the debounced retry carries the name in the attribution ledger.
- Readers know every agent through `isAgentAuthor` (server and web); the web keeps its own copy of the list in `agentReview.ts`.
- The product identity is applied per git invocation (`-c user.name/user.email`, and the subject rewrite) inside gitops, so callers outside it (routes.ts, index.ts, mcp/stdio.ts, zotero.ts still pass `'aldine: …'`) produce `laytekz: …` commits without being edited, and existing repositories, whose config says `user.name=Aldine`, need no migration.

## Deviations
- No `AGENT_AWARENESS_USER` function: the constant stays (its colour and flag), and the name comes from `agentDisplayName(owners, agent)`; the session and each presence carry the agent.
- The label rides an AsyncLocalStorage scope set in `mcp/server.ts` instead of a field on `McpIdentity`, so `mcp/tools.ts` (not WP42's) needed no change.
- The stdio MCP transport (`mcp/stdio.ts`) has no header and stays Claude.
- Specs 16, 40 and 77 needed no change: Claude's strings are unchanged, and spec 40's header assertions were already corrected in HEAD. The Codex case is spec 242.
- A person whose account name is "Codex" is read as the agent, as a person named "Claude" already was upstream.

## Privacy notes
No new hosts, storage or data. The agent name comes from a request header and lands in commit metadata, presence and the project's last-edit record, where "Claude" already did. Commit metadata now says "Laytekz <laytekz@localhost>" and "…@laytekz.local" instead of upstream's name; both are visible to whoever a project is synced to.
