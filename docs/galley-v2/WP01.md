# WP01 contract-freeze

## Summary
Every contract of plan section 2 now exists as code: the type files, a stub
for each signature (bodies throw "Not implemented yet … (<WP>)"), a stub module
for each of the 23 feature ids on the web and server side and for the three
shell features, the three static manifests, the settings registry, the
ownership manifest and tooling under `scripts/v2`, this directory's README,
and the e2e mock router. Nothing imports any of it from an existing code path,
so no user sees a change. The decisions taken where the plan was ambiguous or
did not fit the code are README section 5 (D1–D18).

## Tests
- `scripts/v2/remote.sh WP01 'npm run typecheck -w apps/web'` and `… -w apps/server`: both pass (the new files are in tsc's file list).
- `npm run test -w apps/web` on the build machine: 75 files, 706 tests pass.
- `npm run test:unit -w apps/server` on the build machine: 148/151 files pass. The three that fail, `compiler-sandbox`, `manual-commits` and `preamble-cache`, fail the same way on the untouched V1 copy in `~/laytekz-v2/server`: the build machine lacks `unzip`, and its latexmk and PDF text tools behave differently. Treat those three as the baseline.
- `scripts/v2/desktop-test.sh` on the Mac: the desktop suite, 60 tests, passes.
- The mock router against the V1 mock, 27 requests (status, headers, bodies) and the venue registry file: byte-identical.
- `node scripts/v2/selftest.mjs`: the glob tests, `check-ownership.mjs --lint` and `check-contracts.mjs` pass; the lint was also shown to catch an injected overlap.
- `scratch-sync.sh` run twice at once on a new commit: one upload, both trees complete.
- `scripts/v2/e2e-slot.sh -c e2e tests/05-zotero.spec.ts` in a scratch tree of HEAD plus these files: 8 of 8 pass (slot 1, app :3110, mocks :3111, compiler :4010 on loopback with a token), with the mock router and the V2 config; no process or port was left behind. The build machine's compiler has no latexindent (Perl's YAML::Tiny is missing), so specs that format a document cannot pass there.
