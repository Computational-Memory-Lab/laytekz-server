# WP44 pet-runtime

## Summary
The desk pet (feature 14) is visible now. On a server whose operator
supplied a pet image, a signed-in person can turn on "Desk pet" in
settings (off by default). The pet fades in from its silhouette on a free
stretch of the editor bar, with its paws on the bar's bottom line. It
breathes and tilts now and then, reacts to typesets, errors, people
joining and (optionally) new comments, dozes while you are away and stays
still under reduced motion. It freezes in a hidden tab. You can pet it,
drag it to another spot, send it away for an hour (double-click) or use
its right-click menu. Only you see it: nothing reaches the document,
awareness, the project or the server.

### R1: apps/web/src/commands/index.ts: palette toggles respect `visible`
- **Anchor:** `    if (!def.palette || def.control?.kind !== 'switch' || def.scope === 'project') continue;`
- **Hunk:**
  ```diff
  +    // Galley: V2 a row the settings page hides (no server support) has no palette toggle either.
  +    if (def.visible && env && !def.visible(env)) continue;
  ```
  with `settingToggleCommands(defs, env?: SettingsEnv)` and Editor.tsx passing
  the page's settings environment.
- **Why:** `pet.on` is `palette: true` in the engine, but the generic toggle
  would list "Turn desk pet on" on servers without a pet image.
- **Without it:** nothing breaks. `features/pet/settings.ts` sets
  `palette: false` on `pet.on`, and `index.ts` adds the same row (same id,
  `setting.pet.on`) only when the server offers a pet. Once R1 lands, the
  override and that command can go.

## Deviations
1. **Settings: no "Hide for an hour / Back at 15:42" row** in the Desk pet
   section. "Away until" is a device key outside the registry (WP39), so a
   row needs a custom control. The palette ("Hide the desk pet for an hour",
   "Bring the desk pet back"), the pet's menu, the double-click and the
   toast's "Bring back" cover it.
2. **The reduced-motion note** is part of `pet.on`'s hint (a function of
   the moment the page renders it), not a separate line.
3. **Coming back after a hidden stretch:** when a control grows into the
   stretch the pet is hidden before the paint; it reappears as soon as the
   stretch has room again (the engine's hysteresis, +40 px to place and
   +24 px to stay, keeps it from flickering), not after 2 s.
4. **The files perch** is WP06's spacer in the sidebar's tab row (not the
   tree's footer). It is used when it has room, which at the default sidebar
   width is often not the case.
5. **Commands** are in the palette group "View".

## Privacy notes
- The only request the runtime makes is the same-origin image
  (`/api/instance/pet?v=…`, WP39), signed in and `private`; it is drawn as a
  CSS background so it cannot be dragged out of the page.
- Settings follow the account (WP39's definitions, WP02's sync). "Away
  until" stays in this browser (`aldine.pet.awayUntil`).
- Nothing about the pet goes into Yjs, awareness, the project, the PDF or
  the ZIP; collaborators never see it. Only local events move it: a
  collaborator's edit is never fed to it.

## For later packages
- The pet sits in `editor.overlay` at `z-index: var(--z-pet)` (16) on the
  `[data-perch]` spacers. A package that adds a control to a header needs
  to do nothing: the pet measures the stretch and moves or hides.
- `data-testid`s: `desk-pet` (the clip box, with `data-pet-perch`,
  `data-size`, `data-pose` = the brain's phase, `data-motion` = the motion
  playing or `rest`), `desk-pet-body`, `desk-pet-menu` and its items
  (`desk-pet-menu-pet`, `desk-pet-menu-move`, `desk-pet-move-<spot>`,
  `desk-pet-menu-away`, `desk-pet-menu-settings`, `desk-pet-menu-off`),
  `desk-pet-target-<perch>` while dragging.
