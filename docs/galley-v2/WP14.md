# WP14 table-engine

## Summary
The table engine for feature 4. A whitespace-only, idempotent aligner pads cells by the column spec. It handles every table environment in the vocabulary, overflows `\multicolumn` and very wide cells, and never touches tables written on one line. The package also adds the table model (moved out of the Visual widget, with three scanner fixes), a family table, a display-width counter, the insert template, and commands for Source mode. It adds the keep-aligned extension and new row and column operations, built from one `TABLE_OPS` list. In the app today, the Visual grid's "Rows and columns" menu has new items: Move row up and down, Move column left and right, and a "Column alignment" submenu (Left, Centered, Right). WP18 wires the rest: the button, ⇧⌥A, palette entries, settings, keep-aligned and `afterFormat`.

## Deviations
- **Rows mode is not built.** The report's "one row per line" mode for the Align command (split rows that share a line, join a row broken between cells) does not exist. The aligner always keeps line breaks, and a row that shares its line with another row, or with the `\begin` line, is skipped. `AlignOptions` has no `lines` field.
- **Indentation.** Every aligned row that starts its line gets the shallowest indentation among the rows whose first cell has text. A right or centred first column pads some rows' fronts, so taking the first row's indentation would not be idempotent.
- **Equation alignment, empty cells.** In the `align` family, an empty cell is written `& &`. The spaces after a non-empty cell's `&` are kept as typed.
- **Not built:** "Use booktabs rules" and "Use \hline rules" (rule-style conversion), and cut and paste of columns (left out by the plan).

## For later packages
- **WP18: wiring F4.**
  - **⇧⌥A and the palette:** `alignTableCommand(view, opts)` and `alignAllTablesCommand(view, opts)` from `editor/tables/commands.ts` return `'aligned' | 'none' | 'already' | 'alreadyAll' | 'noTables'`. Show `ALIGN_MESSAGES[outcome]` as the toast. Each edit is one `applyExplicitEdit` step with userEvent `input.align`.
  - **Source-mode row and column operations:** `runTableOp(view, op)` and `tableOpProblem(view, op)`, over `TABLE_OPS` (labels and groups; `group: 'align'` is a submenu).
  - **Keep-aligned:** `keepAligned({ options: () => enabled ? { justify, maxWidth } : null, peerInside })` from `editor/tables/keepAligned.ts` is a ViewPlugin for the feature's compartment. Only `input*` and `delete*` userEvents start it, never `input.align`, `input.format`, `input.visual`, `input.table` or `input.auto`. Composing the realignment into Visual grid edits is not done.
  - **`afterFormat`:** `alignAfterFormat(state, opts)` from `locate.ts` returns the whole document's alignment as a ChangeSpec, or null.
  - **Picker:** `tableTemplate(spec)` from `insert.ts` gives the exact text, with `fields` (cells row by row, then caption, then label) and `firstCell`. Also there: `needsPackage(lines, documentPackages(state))`, `defaultRuleStyle`, `insertRefusal(contextAt(state, pos))` and `floatRefusal(...)`. The template contains no `${`, `#{` or `\{`.
  - **Suggested settings:** keep aligned (automatic, default on), "Pad cells by the column's alignment" (spec or left), and the overflow width (default 40; 0 means no limit).
- **Shared helpers:** `tableAt(state, pos)`, `tablesIn(state, from, to)` and `cellAt(model, offset)` in `locate.ts`; `tableModelFromSource(src, family?)` in `model.ts`, which works for any vocabulary environment, not only grammar `TabularEnvironment` nodes; and `familyInfo(name, family?)` in `families.ts`.
- **Visual grid:** it still builds its model from the syntax node (`tableModel(doc, node)`), unchanged apart from the scanner fixes. `\tabularnewline` now ends a row, and a nested environment or `\verb` stays one cell.
