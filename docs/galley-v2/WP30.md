# WP30 build-outputs-server

## Summary
Every full typeset now builds glossaries, acronyms, the symbols glossary and
nomenclature as well as the bibliography (latexmk rules that call makeindex
directly), says when a glossary could not be built (xindy, bib2gls, switch
off) and when a bibliography is stale or missing because a `.bib` is not in
the project. The server lists what the last typeset generated, copies one
generated file (`.bbl`, `.ind`, `.gls`, `.acr`, `.sls`, `.nls`) into the
project in one commit, builds an arXiv-ready ZIP (with 409 "Typeset first"),
and serves the PDF named after the project. A branch whose copy of the main
document was renamed or deleted typesets the root it would pick instead of
failing. New projects no longer ignore `*.bbl`, and imported archives keep
their own `.gitignore`. The switch is the project setting `outputs.buildAux`
(on by default). Nothing here edits a source file unless a member asks
(Add to project); every change is one commit that History can revert.

## Routes (for WP34)
All in `apps/server/src/features/outputs/server.ts`. Reads are open to anyone
who can open the project (viewers, link visitors, tokens with access); the one
write is members only (not in `tokenWrites` or `viewerWrites`).

- `GET /api/projects/:id/output/list?branch=main` →
  `{ root: string|null, outDir: string|null, typesetAt: ISO|null, files: [{ name, path, size, mtime: ISO, fromLastRun, keepable, tracked?: 'same'|'differs'|null }] }`.
  `path` is what `GET …/output?branch&path=` serves (download, View).
  `fromLastRun` compares with the `.aldine-run` sentinel. Dotfiles, `fmt/` and
  links are left out. `tracked` is present only when `keepable` (the file is
  one of `.bbl .ind .gls .acr .sls .nls`) and compares with the project file of
  the same name beside the main document. `no-store`.
- `POST /api/projects/:id/output/keep {branch, name}` (members; WP34 confirms
  first) → `{ ok, path, created, unchanged, gitignore: string|null, commit: string|null }`.
  Copies `<rootDir>/.aldine-out/<name>` to `<rootDir>/<name>` (through the open
  document when someone has it open), appends `!/<path>` to the `.gitignore`
  whose rule ignores it (`git check-ignore -v`), one commit: "Add main.bbl from
  the last typeset" / "Update main.bbl from the last typeset" under the
  person. With manual commits on, no commit (`commit: null`). Undo = `POST
  …/revert {hashes:[commit]}`. 400 for other files or names, 404 when the
  typeset made no such file, 409 when the target is a folder or link, 429.
- `GET /api/projects/:id/export/arxiv?branch=main` → the ZIP,
  `Content-Disposition` "<Project> (arXiv).zip", warnings also in the header
  `x-laytekz-warnings` (URI-encoded JSON array). With `&check=1` → JSON
  `{ ok, name, warnings: string[], files: string[], rerooted: string|null }`
  without building the ZIP: WP34 calls it first and shows the warnings with
  "Download anyway"; no warnings → download directly. 409
  `{ error, code: 'typeset-first' }` when there is no typeset, the last one was
  a draft (`.aldine-draft`), or a `.bib` the document loads is newer than the
  last typeset. WP34 runs a full typeset and retries on 409.
- `GET /api/projects/:id/download/pdf?branch=main[&inline=1]` → the PDF,
  `attachment` (or `inline`) named "<Project>.pdf" with an ASCII fallback. 404
  `code: 'typeset-first'` without a PDF.
- `GET /api/capabilities` gains `outputs: { list, keep, arxiv, pdf }` (all
  true), so a client can tell this server has the routes.
- Project setting `outputs.buildAux` (boolean, members may change it, visible,
  copied with the project; absent = on).

## Deviations
- **Routes live in the feature, not `routes.ts`** (plan §3.3 lists them under
  `srv/features/outputs`): the analyst's `Content-Disposition` on `/output`
  and `/archive?for=arxiv` became `GET …/download/pdf` and `GET …/export/arxiv`,
  so V1's `/output` and `/archive` handlers are untouched.
- **`check=1`** on the arXiv route (not in the plan): the analyst's "warnings
  in a small dialog before the download" needs them before the bytes.
- **Keepable files** add `.sls` (the glossaries `symbols` glossary) to the
  analyst's `.bbl .ind .gls .nls .acr`.
- **The symbols glossary** (`.slo → .sls`) and the glossaries `numbers`
  glossary (which shares `.nlo/.nls` with nomencl; the rule picks the style
  from the `.aux`) are built too.
- **makeindex runs inside the output folder** (latexmk's own `pushd`/`popd`):
  under `openout_any = p` makeindex refuses to write `.aldine-out/main.gls`.
- **xindy glossaries get an empty output file**: a rule that leaves its target
  missing makes latexmk fail the whole typeset, where V1 succeeds with an
  empty glossary. The warning row says why.
- **The "Typeset first" staleness test** compares each `.bib` with the
  `.aldine-run` sentinel (the last typeset's start), not with the `.bbl`:
  latexmk leaves an unchanged `.bbl` alone when a `.bib` was touched without
  a content change, which would refuse the export forever.

## Privacy notes
No outbound hosts, no new stored data. The arXiv ZIP is built from what the
project already holds; `git hash-object -w` writes the added blobs (the
generated files and an optional 00README.json) as loose objects in the
project's own repository, as `workingTreeId` already does.
