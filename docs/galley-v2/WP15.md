# WP15 label-cite-index

## Summary
The server now knows which citation and cross-reference commands a document
uses and what every label names. `GET /api/projects/:id/cite-setup` answers
the citation family (biblatex, natbib, apacite or plain BibTeX; the apa7
class's `biblatex`, `natbib` and `apacite` options decide first), the
cross-reference packages (cleveref and its capitalise option, hyperref,
amsmath, varioref, nameref) and the loaded `.bib` files. `GET …/labels` entries
now carry kind, environment, title, line and offset, commented-out labels are
gone, and duplicates are flagged. `.bib` entries carry their line and the
identifier fields. Nothing changes on screen yet: the citation picker (WP19),
link following (WP20) and the cross-reference picker (WP26) read these.

## Requests

### R1: apps/server/src/routes.ts: `/labels` sends V1's shape unless `detail=1` (optional)
- **Anchor:** `app.get<{ Params: { id: string }; Querystring: Q }>('/api/projects/:id/labels', async (req) =>`
- **Hunk:**
  ```diff
  -  app.get<{ Params: { id: string }; Querystring: Q }>('/api/projects/:id/labels', async (req) =>
  -    labelIndex(req.params.id, req.query.branch || 'main'));
  +  // Galley: V2 (WP15) ?detail=1 adds kind, env, title, line, from, duplicate (indexes.labelIndex)
  +  app.get<{ Params: { id: string }; Querystring: Q & { detail?: string } }>('/api/projects/:id/labels', async (req) => {
  +    const labels = await labelIndex(req.params.id, req.query.branch || 'main');
  +    return req.query.detail === '1' ? labels : compactLabels(labels);
  +  });
  ```
  and `compactLabels` added to the `./indexes.js` import on line 28.
- **Why:** the plan's contract is `GET …/labels?detail=1`. A feature cannot register a second handler for `/api/projects/:id/labels` (Fastify refuses a duplicate route), so today the existing route returns the detailed entries whatever the query says.
- **Without it:** `?detail=1` already works (every reply is detailed); replies without it carry extra fields, which the V1 client ignores. Nothing breaks either way.

No request touches a contract type.

## Deviations
1. **`/labels` always returns the detailed entries** until R1 lands (see R1). `labelIndex()` is now `async` (it reads the project's root file for `\appendix`); its two callers (`routes.ts`, `mcp/tools.ts`) already sit in async handlers, and Fastify awaits the returned promise, so `routes.ts` needs no change.
2. **Label entries** carry `envTitle?` (the printed theorem name) besides the plan's fields. `kind` is one of `figure subfigure table subtable equation item theorem listing algorithm footnote part chapter section subsection subsubsection paragraph subparagraph appendix other`. Headings after `\appendix` (in the file, or in a file `\input` after it) have `kind: 'appendix'` and `env` = the sectioning command. `from` is the offset of the `\label` backslash in the file's text with CRLF/CR turned into LF (CodeMirror's positions); `line` is 1-based. Equation titles are the row's TeX source (label and `\\` dropped); every other title is plain text (`texText`), short caption first.
3. **Masking** is `labels.maskTex` (comments with the same rule as `bibload.maskComments`, plus `\verb` arguments and the bodies of `verbatim`, `Verbatim`, `lstlisting`, `minted` and `comment` environments). It is its own copy because `bibload.ts` imports `store`/`config`, which create data directories at import; the pure modules and their tests must not.
4. **`/cite-setup`** takes `?root=<path>.tex` to ask about another root file (the project's root by default; a path with `..` or a backslash falls back to it) and `?branch=` (400 for an invalid name).
5. The crossrefs feature registers nothing (D17 gave it the `…/labels` registration, which lives in `routes.ts`).

## For later packages
- **`GET /api/projects/:id/cite-setup?branch=`** (any reader, tokens included) returns `CiteSetup` (`apps/server/src/citesetup.ts`):
  `{rootFile, documentClass, classOptions, family: 'biblatex'|'natbib'|'apacite'|'bibtex', familySource, biblatexStyle, natbibCommands, apa, label, packages, cleveref, cleverefCapitalise, hyperref, amsmath, varioref, nameref, bibFiles, files}`.
  `label` is the picker header text ("biblatex · APA", "natbib · APA", "apacite · APA", "natbib", "BibTeX"). `family` follows the plan's table: apa7[natbib] is `natbib` (apacite with natbibapa), so `\citep`/`\citet`. `apa` is true for the apa7 class, a biblatex apa style, or apacite; WP26 uses `documentClass === 'apa7'` for "`\Cref` everywhere".
- **`GET /api/projects/:id/labels?branch=&detail=1`** returns `LabelDetail[]` (`apps/server/src/labels.ts`): `{label, file, line, from, kind, env, title?, envTitle?, duplicate?}`. Pass `detail=1` even though today's route ignores it (R1 makes it matter).
- **`GET /api/projects/:id/bib`** entries gain optional `line`, `editor`, `doi`, `url`, `eprint`, `eprinttype`, `pmid`, `crossref`.
- Use them through `apiRequest` (web/api.ts); the wire types above are the contract (the web side has no copy of them; define the client type next to the consumer).
- `texText` (bib.ts) is the TeX-to-display-text cleaner; `labelsIn`, `theoremsIn`, `maskTex`, `markDuplicates`, `appendixFiles` (labels.ts) and `citeSetupOf`, `splitOptions` (citesetup.ts) are pure and safe to import anywhere on the server.
