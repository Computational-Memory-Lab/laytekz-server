# WP24 wordcount-engine

## Summary
A rule-based word-count engine (feature 13). Every word in a document gets a part and a kind. The parts are title page, abstract, main text, statements, appendix, supplementary material, references and excluded. The kinds are text, headings, citations, footnotes, captions and tables. A rule chooses which cells count. The engine has two byte-identical copies, one for the server and one for the web app. The server serves the full breakdown under the rule in force at `GET /api/projects/:id/wordcount/breakdown`. The rule is stored in the project setting `wordcount.rule`; when the project has none, the asking account's preference of the same name applies, and otherwise the built-in "Main text" rule. By default the count leaves out tables, captions, supplementary material, references, statements, appendices, the abstract and the title page. The existing `/wordcount` route and the MCP tool give the same count once R1 and R2 land. The status, popover and rule editor are WP27's.

## Deviations
- The plan places rule resolution, the inline walk, citation estimates and the cache key in `srv/indexes.ts`. They are in `srv/wordcount/count.ts`, because WP15 owns `indexes.ts` in this wave (R1 hooks them up).
- **Stored rules are sparse.** Any field may be left out and takes its default (`resolveRule`). The account preference is limited to 2 KB, so a rule cannot carry the full default pattern lists. A preset other than `custom` decides the parts and kinds.
- **The account default** uses WP03's account preferences (`wordcount.rule` in `/api/account/preferences`). The report's `User.wordCount` column is not needed: the datastores are never edited in V2.
- **Acceptance figures.** The analyst's generated APA fixture (front 37, abstract 150, …) no longer exists: its scratch scripts are gone. `wordcount-engine.test.mjs` builds its own write-paper-style manuscript, with the same structure, and asserts exact cells: front 22, abstract 14, main headings 4, main text 34, citations 6, footnotes 6, captions 12, tables 13, statements 6 + 11, supplementary 4 + 6 + 3.
- **Heading scopes.** A statements or references scope opened by a heading is not replaced by a matching subheading (Declarations › Funding stays one scope). The same goes for an outer section override: a nested one does not replace it.
- **Citation style detection.** The engine detects numeric citation styles from `\bibliographystyle`, natbib `numbers`, biblatex `style=numeric…` and the `cite` package. It does not use WP15's `citeSetupOf`; a later package could hook that in.

## Privacy notes
No new hosts and no new stored data, apart from the `wordcount.rule` value: a project setting in `project_meta.ext`, visible to members, or an account preference. Neither holds any personal data.

## For later packages
- **WP27:** use `apps/web/src/wordcount/engine.ts`; never edit the twin alone. Edit the server copy and copy it across.
  - The full breakdown is `GET /api/projects/:id/wordcount/breakdown?branch=`. It returns `WordCountResult` (`wordcount/count.ts`): `segments` (each with file, occurrence, line, heading, level, `cont` and a sparse `tally`), `occurrences` (with `entry`/`exit` `ScanState`), `macros` (the definitions that `ScanState.macros` counts into), `sections`, `why`, `unresolved`, `citeWords`, `otherDocuments`, `unreachable`, `characters`, `readingMinutes`, `target` and `abstract`, plus `rule`, `ruleSource` and `ruleName`.
  - **The splice:** `countText(text, rule, { file, entry: occurrence.entry, macros: result.macros, citeWords: k => result.citeWords[k] ?? 2 })`. Refetch when `!sameState(newExit, occurrence.exit)`.
  - **Selection:** `printedWords(countText(sel).tally)`.
  - **Section overrides** are stored under `sectionKey(title)`.
  - The project rule is the project setting `wordcount.rule`: register the web `SettingDef` with `scope: 'project'` in `features/wordcount/settings.ts`. The account default is the account preference `wordcount.rule`.
  - `%WC:<part>` markers (`%WC:supplementary` … `%WC:main`) and `%TC:ignore`/`%TC:endignore` are honoured.
- `wordcount/validate.ts` limits: 50 patterns per list, 100 characters per pattern, 200 section overrides, targets from 1 to 1,000,000.
