# WP40 inline-suggest

## Summary
Feature 12's Tab completion without a model: while you type a long word
that the project already uses, the rest of it appears in grey after the
caret. Tab accepts it as one undo step, ⌘→ / Ctrl+→ takes the next word,
Escape hides it, and ⌥\ / Alt+\ asks for one on purpose. The vocabulary is
the prose of the open file plus the project's other `.tex` files; nothing
leaves the browser beyond the project files it already reads from its own
server. Source mode only, switched by Settings › Completion › "Inline word
suggestions" (on by default, an automatic setting, so off under the legacy
specs' `automatic-off`). The suggestion is a local decoration: collaborators
never see it, and their edits never trigger it. The model (WP43) plugs into
the same core through `provider.ts`; `promptContext.ts` and `postprocess.ts`
already hold the prompt window and trimming rules it needs.

## Deviations
- **A visible list, not the completion status, owns the moment.** The plan
  says the suggestion is hidden "while the list is open or pending". With
  "Show completions: as I type", `@codemirror/autocomplete` 6.20 marks every
  source pending after every typed letter until its query returns (100 ms
  later), even in prose where no list ever opens, so honouring "pending"
  would hide the ghost on every keystroke. The ghost is cleared, and Tab
  declines, while a completion list has options on screen
  (`currentCompletions(state).length > 0`) or a snippet field is active
  (`hasNextSnippetField`). Tab pressed before a pending list appears takes
  the ghost the person can see.
- **Setting:** one switch, `suggest.words` (account scope, section
  `completion`, `automatic: true`, default true, `palette: true`, label
  "Inline word suggestions", so the palette reads "Turn inline word
  suggestions off"). The report's key `aldine.suggest.words` is the store's
  default mirror key for this id. Phones are not special-cased (the report's
  "off by default on phones" is not built).
- **Context:** suggestions appear only where `contextAt` says `text` or
  `table` with no math, no preamble and no argument other than a text one.
  Comments are excluded too (the report did not list them; conservative).
- **Late model answers** are shown only when the document and caret are
  unchanged since the question (every keystroke aborts the question in
  flight), rather than "when what was typed meanwhile is a prefix of it".
- **No live region** ("Suggestion available, Tab to accept") yet; the ghost
  span is `aria-hidden`.
- **Visual mode:** not built (`modes: ['source']`), as the plan says for v2.0.

## Privacy notes
- No new host. The word list is built in the browser from the open file and
  from the project's other `.tex` files, read through the existing
  `GET /api/projects/:id/file` (the same server and route completions use),
  at most 40 files of at most 512 KB, again only after a file's mtime changes
  and at most once a minute. Nothing is stored apart from the switch
  (account preferences, mirrored in localStorage as `aldine.suggest.words`).
- The suggestion is never written to Yjs or awareness until Tab accepts it.

## For later packages
- **WP43 (model):** implement a `SuggestionProvider` with `deferred: true`
  (asked 250 ms after the last keystroke, aborted through `signal` by the
  next keystroke or caret move) and call `registerSuggestionProvider(p)`
  from `provider.ts`. Build its prompt with `promptContext(doc, pos)` (fixed
  start for the prompt cache, no preamble, suffix to the end of the next
  line) and trim its output with `postprocess(raw, prefix, suffix)`. The
  word provider answers first mid-word; a deferred provider is asked when the
  word provider has nothing. Its module must be imported from somewhere that
  runs: `features/suggest/index.ts` is WP40's, so WP43 needs a one-line
  request there (for example `import './model/register';` inside the
  `extension(ctx)` path, lazily) or registers from its own settings row.
- **Key chains:** Tab 80 (`suggest.accept`), Mod-ArrowRight 80
  (`suggest.acceptWord`) and Escape 90 (`suggest.dismiss`) act only while a
  ghost is at the caret; otherwise they pass the key on.
- **Accepted text** is dispatched with user event `input.complete`
  (`ACCEPT_EVENT`), between two undo boundaries.
