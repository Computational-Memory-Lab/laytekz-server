# WP37 highlight-ui

## Summary
The highlighter now has its full interface on top of WP32's data layer: a
split button in the editor pane header (`editor.tools`, order 300) that
highlights the selection with the current colour, removes it again, or opens
the card of the highlight at the caret; a dropdown with the six presets, "Your
colours", "Custom colour…", remove/clear actions, next/previous, the list and
settings; a "Highlight …" entry and a "Highlight colour" submenu in the
editor's right-click menu inside a selection (Shift+right-click keeps the
standard menu); ⇧⌘H using the current colour; a card on a click inside a
highlight; a custom-colour dialog with hex validation, a two-theme preview and
readability warnings; a "Highlights" tab on the sidebar's main row listing this
file's or the project's highlights with colour and "Only mine" filters;
colour-blind patterns; bars beside highlighted display math and tables in
Visual mode. Every part switches off with Settings → Highlighter.

## Deviations
- **Visual-mode bars live in the feature, not in `visual/index.ts`.** The feature's compartment is rebuilt on a mode change (WP05), so `extension(ctx)` adds the `visualBars()` layer only when `ctx.mode() === 'visual'`. It reads `atomicField` (import only) and draws a 3px bar beside every widget that spans lines (display math, tables, figures) and is covered by a shown highlight. `visual/index.ts` stays untouched, which keeps the byte-stable visual layer out of this package's diff.
- **The button is hidden for viewers and showcases** (`page.canEdit()` false) and **disabled** while the file loads or is read-only by a rule (the editor's `state.readOnly`); the analyst wanted it hidden on read-only files, but the load gate and a read-only rule look the same from a feature.
- **⇧⌘H** (WP32's binding and command, kept) now paints with the current colour (the last colour chosen when "Remember the last colour" is on, else the default colour) and, with no selection and the caret in a highlight, opens the card with focus on its colours.
- **The preset palette commands** (`highlighter.highlight.<preset>`) now paint (never a toggle) and make that colour the current one.
- **New settings** (account scope, device-mirrored as `aldine.highlighter.*` like WP32's): `highlighter.rememberLast` (true), `highlighter.contextMenu` (true), `highlighter.card` (true), `highlighter.patterns` (false), `highlighter.customColors` (`[]`, at most 8 `#rrggbb`, custom control "Your colours" with remove buttons). The current colour itself is a per-browser convenience in `localStorage['aldine.highlighter.last']`.
- **Clear actions** are titled "Clear my highlights in this file" and "Clear all highlights in this file…" (the analyst's wording); the confirmation counts co-authors' highlights, and both end with a toast "Cleared N highlights" with Undo (the editor's undo manager).
- **The card closes after an action** (a colour, Remove, Select text) rather than staying open on the repainted highlight.
- **The list's project scope** opens another file at the highlight's position (`page.openFile(path, {pos})`); in the open file it selects the highlight. Row menus (Change colour) are not built: file-scope rows have a remove button, and the card changes colours.
- **New commands:** `highlighter.custom` ("Highlight with a custom colour…"), `highlighter.next`, `highlighter.prev`, `highlighter.list` ("Show highlights"), `highlighter.settings` ("Highlighter settings…"). Viewers and showcases keep only the reading ones.
- **The highlighter's `contextMenu` entry makes WP05 install the editor's app menu for everyone** (it installs once any enabled module has entries). The menu still opens only for a plain right-click inside a selection that existed before the press; with `highlighter.contextMenu` or `highlighter.enabled` off the entry returns no items, so WP04's policy leaves the native menu.
- **Not built (left for later):** paste memory ("Pasted text keeps its highlights": a clipboard output filter that remembers the copied runs and repaints them on a matching paste, behind its own setting); the phone More-sheet entry (the pane-header button shows on phones, and the palette has every command).

## Privacy notes
- `localStorage['aldine.highlighter.last']`: the colour last chosen in this browser (a preset id or `#rrggbb`).
- The new settings, "Your colours" included, are account scope: with account sync on, they are stored with the account's preferences on the server.
- The project list calls WP32's `GET /api/projects/:id/highlights` (same origin). No other host is contacted; "Pick from screen" uses the browser's own EyeDropper and sends nothing.
