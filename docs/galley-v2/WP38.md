# WP38 stats-editor

## Summary

Statistics commands work in the editor (feature 16), on top of WP33's core.
Typing `\pv` lists `\pval` in the completion list (Enter or Tab inserts it),
and Tab right after a typed trigger such as `\ttest` expands it too. The
statistic is written as plain LaTeX in the project's house style, with fields
for its numbers: Tab and Shift+Tab move between them, Enter finishes, Escape
stops, and each number is formatted when its field is left (`0.0004` becomes
`< .001`). Empty optional parts (the MSE in `\anova`) are removed at the
finish. ⇧⌘U (or the "p" button in the editor header, or "Insert statistic…"
in the palette) opens a searchable picker of the whole catalogue. Pasting R or
Python test output offers to convert it (one click, one Undo). The palette
also has "Convert to APA statistics" (selection or paragraph) and "Reformat
statistics in this file". Statistics typed in prose get the house style when
automatic math mode wraps them. Settings › Statistics holds four switches and,
over a project, the shared house style.

## Requests

### R1 (optional): apps/web/src/features/automath/rules.ts: skip statistic fields

- **Anchor:** in `planFor`, the line `  if (!textual(ctx) || !textual(contextAt(state, line.from + start, { side: 1 }))) return null;`
- **Hunk** (plus `import { inStatField } from '../stats/api';`):
  ```diff
  +  // Galley: V2 statistics (WP38) the numbers typed into a statistic's fields are its own.
  +  if (inStatField(state, at)) return null;
  ```
- **Why:** plan §3.7 asks automations to leave the active field ranges alone. Most fields sit inside `$…$`, where automatic math mode never acts, but a few are in prose (`\binomtest`'s counts, a CI level).
- **Without it:** typing a number into a prose field and then a space or comma could be wrapped by automatic math mode; the statistics fields never type spaces themselves, so this needs the person to type one.

## Deviations

- **Settings** (section `statistics`):
  - `stats.style` (project scope, custom control `StyleControl.tsx`): the house style, stored as WP33's diff from APA 7 (the server validator is WP33's). The control shows "APA 7" or "Custom" and "Reset to APA 7" (stores `{}`); test ids `stats-style`, `stats-style-name`, `stats-style-reset`, `stats-style-<key>` (for example `stats-style-leadingZero`).
  - `stats.triggers` (account, switch, automatic, palette, on): triggers in the completion list and Tab after a typed trigger.
  - `stats.formatOnLeave` (account, switch, automatic, on): off keeps the fields and leaves the numbers as typed.
  - `stats.typed` (account, switch, automatic, on, dependsOn `automath.wrap`): the automatic math formatter.
  - `stats.pasteOffer` (account, switch, automatic, on).
- **Completion ranking:** the triggers carry `boost: -5` and the detail "<title> · statistic" instead of a "Statistics" completion section. CodeMirror sinks a whole section below every option without one, so `\pv` would have put `\providecommand` (a loose match) above `\pval`, and Enter would have inserted the wrong thing. With the boost, a real command that matches as well still comes first (`\ci` lists `\circ` before `\ci`).
- **The paste offer is the feature's own bar** (`paste-stats-offer`, button `paste-stats-convert`, `paste-stats-dismiss`; gone after 15 s), drawn by the `editor.overlay` slot, not a toast: `EditorPageCtx.toast`'s action has no test id (Editor.tsx maps it to `{label, onClick}`), and the plan's acceptance names `paste-stats-convert`.
- **The picker** is a `CommandPalette` inside `data-testid="stats-picker"` (rows `palette-item-stats-<entry id>`, the trigger and a sample as the hint), not KaTeX previews per row.
- **Field placeholders** (`.cm-stats-ghost`, test id `stats-field-ghost`) show the field's label through CSS `::before` on the character after the empty field (a widget only at a line end); no placeholder text enters the file. A widget beside the caret made Chrome put text typed after a Tab into the previous field (CodeMirror 6.43 left the DOM caret on an element boundary next to the uneditable widget); the e2e spec covers it. A value kept because it is out of range gets a wavy underline and the reason as its title. The small "→ p < .001" hint under the active field is not built.
- **Undo:** the insertion and each formatting are their own undo steps (`closeUndoStep` before and after); the first Undo after a Tab brings back the number as typed.
- **Selection on insert (picker):** a selection the converter recognises is converted instead; a single number fills the first field that is not an interval level; with several cursors only the main one gets the statistic.
- **Editor commands** `stats.convert` ("Convert to APA statistics", selection or the paragraph at the caret) and `stats.reformat` ("Reformat statistics in this file") are palette rows in group Insert; each is one undo step with a toast.

## Privacy notes

No network access. The four switches are account scope (synced with the account's preferences when sync is on); the house style is the project setting WP33 stores on the server for the project's members. The picker and the paste offer keep their state in memory only.
