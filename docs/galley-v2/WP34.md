# WP34 outputs-web

## Summary
The files a typeset generates can now be seen, viewed, downloaded and, after a
confirmation, added to the project. A "Generated by the last typeset (N)"
section under the file tree lists them (the .bbl, the log, the index and
glossary files), with View for text files, Download, and "Add to project…" /
"Update…" for the files a submission needs. The PDF download button gained a
Download menu (PDF, source as ZIP, ZIP for arXiv). Share's downloads read the
same list and offer "For arXiv" in place of V1's "arXiv also needs main.bbl"
hint. The arXiv download typesets first when the PDF is behind the source, asks
before saving a ZIP that has warnings, and every download is named after the
project. The list has an off switch (`outputs.generatedList`), and the
glossary/acronym/nomenclature build has its project switch (`outputs.buildAux`,
read by WP30's server).

## Deviations
- **The Download menu is a second slot item**, not a replacement for the download button. `pdf-download` stays the V1 anchor (spec 69 and WP06's `interim.test.ts` still pass unchanged); the menu trigger `pdf-download-menu` (order 910) holds PDF, Source as ZIP and For arXiv. Hence R1.
- **Add and Update both confirm** (the plan's "confirmed Add and Update", and the owner's follow-up). The analyst's "Update without a dialog, with an Undo toast" was not built: there is no undo for a keep on the server side.
- **The open/closed state of the list** is remembered per project in this browser (`localStorage['aldine.outputs.generatedOpen.<projectId>']`), collapsed by default. The analyst's "collapsed in the Source view, expanded in the All view" was not built: the tree's view choice is FileTree's internal state.
- **`outputs.generatedList` is `automatic: true`** (it shows UI nobody asked for), so the legacy suites (`automatic-off`) never see the new section; spec 234 turns it on itself.
- **`outputs.buildAux` is not `automatic`**: it is a project value read by the server, so the client's `automatic-off` test default must not change what it shows.
- **The arXiv ZIP's name** comes from the client (`<Project name> (arXiv).zip`, `arxivName`), the same name WP30's Content-Disposition gives.

## Privacy notes
Nothing new leaves the browser. The list calls `GET /api/projects/:id/output/list` after each typeset while the section is on (one small request per typeset); View fetches the file through the existing output route. The open/closed state is a per-browser `localStorage` key holding `1`.
