# WP17 console-terminal

## Summary
The desktop app has a console: View → Console (Ctrl+`) opens a terminal panel
over the bottom of the main window, with one shell per tab in the home folder.
The panel resizes with a drag handle, pops out into its own window and docks
again without losing the tabs, and hides with × or Ctrl+` (when it has focus).
The shells run in a utility process that starts with the first tab, so nothing
runs until the console is opened. Laytekz → Console Settings… has the off
switch ("Turn on the console", default on) and the shell, font size,
scrollback and cursor. Quitting while a command runs asks first.

## How it works
- **Process layout.** `pty-host.js` runs in `utilityProcess.fork()` (not subject to the `runAsNode` fuse; a native crash ends only that process). Main relays: page → `ipcMain.handle` through `ShellCtx.ipc.handle` (strict sender check) → pty host; pty host → main → `webContents.send` to the one attached console page. Output is batched every 6 ms (64 KB chunks). Flow control: the page acknowledges what xterm has written; main pauses the pty above 1 MB unacknowledged and resumes below 256 KB. Main keeps the last 512 KB per tab, which a newly attached page replays (pop-out, dock, window re-created).
- The plan's `MessageChannelMain` port to the page was not used: relaying through main keeps every call behind the host's sender check, and the throughput is ample for a terminal. Switching later touches only `console-sessions.js`, `console-bridge.js`, the preload and `console.js`.
- **node-pty** is unpacked when packaged (`asarUnpack`). On macOS and Linux it loads through the asar path (node-pty rewrites its spawn-helper path to `app.asar.unpacked` itself); on Windows from `app.asar.unpacked` (its conout worker only understands `node_modules.asar`). From source, `pty-host.js` sets spawn-helper's execute bit (node-pty 1.1.0 ships it 644); packaged, `build/after-pack.cjs` does, keeps only the target's prebuild, and fails the build if it is missing. Windows spawns with `useConpty` and `useConptyDll`.
- **Isolation.** Both pages are in the in-memory partition `laytekz-console` (the host gives it the `laytekz-ui:` scheme and `hardenUiSession`: every other request cancelled, no permissions). `console.html` has its own CSP: `script-src 'self'`, `style-src 'self' 'unsafe-inline'` (xterm adds `<style>` elements), `connect-src 'none'`. Output is drawn as terminal text, never HTML. Links (web-links addon and OSC 8) go over IPC to `shell.openExternal` only for http(s) without credentials. `vetoPermissions: ['clipboard-read']` for the remote page.
- **Environment.** `shell-env.js shellEnv`: the app's environment minus `ELECTRON_*`, `CHROME_*`, `GOOGLE_*`, `LAYTEKZ_TEST_*`, `NODE_OPTIONS` and Node's IPC variables, plus `TERM=xterm-256color`, `COLORTERM=truecolor`, `TERM_PROGRAM=Laytekz` and `LANG=en_US.UTF-8` when missing. Shell: the setting, else `$SHELL -l` (macOS default `/bin/zsh`), PowerShell 7 or Windows PowerShell on Windows.
- **Quit guard.** `before-quit` asks "A command is still running in the console (sleep)." / "N commands …" with Quit / Cancel when a tab's foreground process (node-pty `process`, polled each second and on output) is not its shell. In test mode it records the question in `<profile>/console-quit.jsonl` and answers from `LAYTEKZ_TEST_CONSOLE_QUIT` (`cancel`, or quit by default; from source only).
- **Off switch.** `features.console.enabled` (settings.json, through `ShellCtx.settings`; a default value is not stored). Off closes the panel and the pop-out, ends every shell and the pty host, and hides View → Console; Ctrl+` then does nothing. Console Settings… stays in the app menu so it can be turned back on.

## Deviations
- Output and input are relayed through main instead of a `MessageChannelMain` port handed to the page (see How it works).
- The console page uses an in-memory partition `laytekz-console` (the plan's example used `persist:`); nothing in it needs to persist.
- Ctrl+` hides the panel only when the console page has focus; otherwise it shows and focuses it (VS Code's behaviour).
- No project tabs yet: every tab is a plain shell in the home folder. Opening a project's tab (`/p/<id>` → its own folder and variables) is WP25's, with the agent buttons.
- `@xterm/addon-webgl` and `@xterm/addon-unicode11` are not added: the DOM renderer is fast enough here and keeps the page free of WebGL.
- Closing the pop-out window hides the console; its shells keep running and reappear on Ctrl+`.

## Privacy notes
- No hosts contacted. The console page has no network; the pty host makes no requests.
- `settings.json` gains `features.console.{enabled, shell, fontSize, scrollback, cursorStyle, panelHeight}` (only values that differ from the defaults).
- Terminal output is kept in memory only (512 KB per tab in main), never written to disk.
- The shells inherit the app's environment minus the variables listed above.
