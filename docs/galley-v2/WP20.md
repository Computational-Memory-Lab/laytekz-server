# WP20 link-follow

## Summary
⌘-click (Ctrl-click on Windows and Linux) in the source now follows what is
under the pointer: web and mail addresses, `\url`, `\href` (the whole command,
text included), `\doi`, `\orcidlink`, bare DOIs, `doi:` and `arXiv:` ids, and
in `.bib` files the `url`, `doi`, `eprint` and `pmid` fields open in the
browser through the page's normal external-link path (`window.open`, which the
desktop app hands to the system browser); `\input`, `\include`,
`\includegraphics`, `\bibliography`, `\addbibresource`, `\subfile`, `\import`
and a relative `\href` open the project file; a local `\usepackage` opens the
`.sty`, any other its CTAN page; a `\ref`-family key goes to its `\label`, a
citation key opens its `.bib` entry, and a `\label` (or a `.bib` entry's own
key) finds its references in the Search panel. Holding the modifier underlines
the target and shows the destination (WP04's hint); Alt+Enter follows at the
caret, Shift+Alt+Enter finds references, and a right-click on a link offers
Open link / Copy link address or Go to definition / Find references. Only
http, https and mailto open; URLs with credentials are refused. Nothing here
edits the document.

## Deviations
1. **One handler.** The feature registers one mod-click handler (`links.follow`, priority 50) for addresses and project targets; `links.project` decides inside it whether project targets count. The hint and underline are WP04's; the hint's text is the destination ("Open https://doi.org/…", "Open sec/intro.tex", "Go to fig:x in results.tex, line 12", "Find references to fig:x").
2. **Refused addresses show nothing.** `\href{javascript:…}` and URLs with credentials give no target at all (no underline, no hint), so the ⌘-click adds a cursor there, as the analyst's spec 68 expects. A missing project file or label is a target with an `error` (red hint, never followed).
3. **No key chooser for multi-key chips.** In `\cref{a,b}` and `\cite{a,b}` the key under the pointer is followed; on the command name (or a Visual chip, whose click lands on its edge) the first key is.
4. **Label index lookups** use `GET …/labels?detail=1` and `GET …/bib` (WP15) through `apiRequest`, cached per project and branch, marked stale by any `docChanged`, `filesChanged`, `filesMoved` or `agentWrite` and refetched on the next look (or after 30 s). A label in the open document is found locally without the server. A follow whose key is missing from a cached index refetches once before saying "No \label{…} in this project".
5. **Find references** seeds the project Search panel with `[{,]\s*<key>\s*[,}]`, which matches the key in any command's or `.bib` entry's brace list (`\ref{k}`, `\cite{a, k}`, `\label{k}`, `@article{k,`, `crossref = {k}`), with the regex toggle on and whole word off for that search only.
6. **Settings** (`links.follow`, `links.project`, `links.menu`, account scope, section Editor behaviour) are not `automatic`: none of them changes text. "Show the link hint while ⌘ is held" is not a setting, because the hint belongs to WP04's arbiter, which has no switch for it.
7. **Files it runs in:** `.tex .ltx .sty .cls .dtx .bib .bbx .cbx .md .markdown .txt`; `.md`/`.txt` find bare addresses only.
8. **Not built (left for later):** the confirmation popover the analyst proposed for Alt+Enter when the visible text differs from the destination (Alt+Enter follows at once, as WP04's `followAtCaret` does; the mouse path shows the destination in the hint first); a key chooser for Visual chips with several keys; jumping from `\usepackage` without a local file goes to CTAN, but `\bibliographystyle` without a local `.bst` has no target.

## Privacy notes
- A followed address opens in a new browser tab (`window.open(url, '_blank', 'noopener,noreferrer')`), or a `mailto:` through an anchor; in the desktop app the shell's window-open handler sends it to the system browser. Nothing opens without the person's click or Alt+Enter, and only http, https and mailto, never with credentials.
- "Copy link address" writes the address to the clipboard on click.
- The feature reads the project's own label and bibliography indexes from the Laytekz server; no other host is contacted.
