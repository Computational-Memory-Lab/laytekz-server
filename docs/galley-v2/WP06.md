# WP06 page-host

## Summary
The editor page and the project list are now feature hosts. The page context
(`EditorPageCtx`) and its events exist, along with every slot, feature
commands with `refusedFor`, page-scope keybindings, read-only rules, the
rename interceptors, keyed branch signals and settings routes over both pages.
The V1 preferences are read through `useSetting`. V1's word count and PDF
download button became the interim `wordcount` and `outputs` features. An e2e
probe feature exercises every extension point. A user sees the same editor as
in V1, with two exceptions that land together with WP07's page: Settings opens
a route over the editor or the project list instead of a dialog, and the
account menu gains "Settings…".

## Deviations
- **`pdf.actions` sits after Zoom, not before it** (slots/types.ts says "before Zoom (download button, order 900)"). V1 draws the download button after the zoom controls and before Auto. The acceptance "the download button looks unchanged" wins, so the slot is where the button was: `…zoom-controls, [pdf.actions], auto-toggle`.
- **`boot(app)` runs before the first render of the editor page, and on any other page once the feature manifest has loaded** (requested at idle by main.tsx, as the editor prefetch already was), not strictly "before the first render of a page". Features may import CodeMirror, so `features/manifest.ts` must stay out of the entry chunk. `host.tsx` never imports it statically: Editor.tsx installs it at module scope (`installFeatures(FEATURES)`), and other pages load it with `loadFeatures()`. Home's project rename awaits `loadFeatures()` before asking interceptors.
- **Home slots (`home.toolbar`) appear after the idle load**, so they show nothing for the first second or so after the page opens.
- **`home.accountMenu` and `phone.moreSheet` are not drawn yet**: menus cannot hold components (R1, R2).
- **The settings entry points switch to the page now.** The toolbar Settings button, the phone sheet's Settings…, the palette's 'settings'/'shortcuts', RemoteSync's settings link, Home's "Account settings…", the `?account=sign-in` return and ConnectClaude's Manage all go to the route. The plan gives WP06 "the settings routes and the toolbar entry", and WP07's specs expect the page from `project-settings-open`. In this package's own tree the route shows WP01's placeholder, so the V1 specs that open the dialog (WP07's list) fail there until WP07's page lands. Project settings are reached only through the page, which gets exactly the props the dialog got (`SettingsPageProps.project`).
- **Sections used by entry points:** `project` (toolbar, phone sheet, palette 'settings', RemoteSync, ⌘, on the editor), `shortcuts` (palette), `account` (Home's account item; the sign-in return adds `#sign-in`, which WP07 maps to AccountSettings' `focus='sign-in'`), `connections` (ConnectClaude's Manage). Home's "Settings…" and ⌘, there open `/settings` with no section.
- **`EditorPageCtx.agentWrite.paths`** are the files the agent's session names in branch awareness (its last minute's). The signal itself carries no paths.
- **`docChanged.path`** is the open file. `onDocChanged(true)` is also called after a project-wide replace, an undo and a delete undo, as V1 did to arm auto-typeset; those emit `docChanged` for the open file too.
- **Sidebar panels:** a `sidebar.panels` item without `panel` is not drawn (there is no tab to show it). Pinned items (`panel.pinned`) and plugin pins (`FeatureModule.pinnedPanels`) share the main row, sorted by `order` (core: references 100, zotero 200). A pin whose plugin panel does not exist shows nothing.
- **Files perch:** `data-perch="files"` is a flex spacer in the sidebar's tab row (`.sidebar__tabs`, before the collapse button), the files panel's only header. An inline `margin-left: -2px` cancels the extra row gap the element would add, so the row's geometry is exactly V1's, a full 180px row included. If WP02 changes that gap, change this margin with it.
- **No new contract types.** Non-contract additions: `BranchSignalHandle.onSignal` and `signalListeners()` (branchSignal.ts is WP06's), `samePage` (leaveGuard.ts), `AccountActions.onSettings` (HomeToolbar.tsx), and everything in pageCtx.ts and host.tsx.

## For later packages
- **A feature's module** (`features/<id>/index.ts`) is installed once per tab and filtered (`_probe` only with `aldine.e2e.probe=1`). Its keybindings are registered with WP04's registry, and `boot(app)` runs. `activate(page)` runs per project+branch once the project has loaded, synchronously in a layout effect, so keep it light. It runs before any page event for that project; the returned function runs when the page or branch goes.
- **The page context** reads live values on every call: keep it, never copy what it returns. `page.events.on(name, fn)` returns the unsubscribe; call it in your cleanup. Events: `docChanged` (open file, local or not), `activeFile`, `filesChanged` (each tree load), `filesMoved` (from the 'moves' signal), `compileRequested`/`compileFinished` (`own: false` and `trigger: 'adopted'` for a run another tab, the agent or the branch's last run put on screen), `agentWrite`, `projectChanged`, `projectSettingsChanged` (after the store refetched), `rosterChanged`, `commentsChanged`, `visibility`, `pdfSelection` (from WP05's PdfPane).
- **Slots:** items render with no wrapper element, inside an error boundary and Suspense; a throwing item renders nothing. Order ties keep manifest order. `when` gets `{page, app}` on every render of the host, so keep it cheap. To re-render on page events, use `usePageEvents(page, ['compileFinished'])` from `features/host`. `editor.tools` orders: 100 tables, 200 statistics, 300 highlighter, 400 citations. `pdf.status`: the interim word count is order 100. `pdf.actions`: the download button is 900.
- **Commands:** `commands(page)` is called whenever the palette is open and on every `runCommand`, so `when` and titles may depend on the page now. `refusedFor: ['showcase']` hides a command in read-only showcases, and `['viewer']` hides it from people who may only view. A command id may be run by a keybinding's `command` (page scopes here; editor scope in CodePane) and by `EditorFeatureCtx.runCommand`. The page's own palette ids are runnable too (`'settings'`, `'typeset'`, …).
- **Read-only:** the first non-null `reason(path, page)` makes the open file read-only and shows as the banner `read-only-banner` (below the header, above `editor.banners`).
- **Interceptors:** `fileRename` runs for the tree's rename/move (`via: 'tree'` until R3) and the palette's (`'palette'`). `projectRename` runs for the toolbar name, the settings page's name field and Home's rename (`page: null`). Returning `'handled'` means the page does nothing else: a feature that renames files must send the 'moves' signal (WP28, `signalBranch(…, 'moves', {moves, by, at})`) so every tab, this one included, follows the open file. Send it in the same transaction as, or before, the files-changed bump, or the "removed by someone else" toast can come first.
- **Settings:** `page.openSettings(t)` / `app.openSettings(t)` / `openSettings(t)` from the store all end in `OPEN_SETTINGS_EVENT`, which `OpenSettingsBridge` turns into `/p/<id>/settings/<section>?<search>#<setting>` over the editor (keeping `?branch=`) or `/settings/…`. Closing goes back through history to the entry it was opened from.
- **The probe** (e2e only) is documented in `features/_probe/editor.ts` and `index.ts`. Triggers: `%probe-chain` + Mod-ArrowRight, `\probelink` mod-click, typing `>` after `%probe-`, `\probec` completion, a right-click on the line `%probe-menu`, a PDF selection containing "probe", the file `probe-readonly.tex`, a rename to `*.probe-intercept`, the project name "Probe intercept", and the command `_probe.hello` (unbound; specs set a chord in `aldine.shortcuts`). Every point it reaches increments `window.__laytekzProbe.counts[...]`.
