# WP36 libraries-panel

## Summary
The sidebar's main row now has a Mendeley tab next to Zotero (feature 20). In it
a member who can edit signs in with Mendeley, links a folder to a `.bib` of
their own (default `mendeley.bib`), syncs it and unlinks it, through WP35's
generic library links. Every linked `.bib` (Zotero, Mendeley, a desktop file, a
web link) opens read-only under a banner that names its source. When a sync
reports citation keys that changed, a notice above the editor offers "Update
citations", which rewrites the keys in the open `.tex` file as one undo step
and lists the other files that still cite an old key. "Sync linked libraries
when a project opens" (on by default, under Automatic changes) is the off
switch for the hourly sync on open, for Zotero and Mendeley alike. Settings ›
Connections has a "Reference managers" row to connect or disconnect Mendeley.

## Deviations
- **Two tabs, not one "Libraries" tab.** The plan renames the Zotero tab "Libraries". Feature 20 (added after the plan) asks for the Zotero and Mendeley connectors on the main row, so the plugin keeps its Zotero tab (`plugin:zotero`, title "Zotero", V1 flow unchanged) and adds a Mendeley tab (`plugin:mendeley`). Only the manifest's name becomes "Libraries". The plugin id stays `zotero`.
- **Feature 20 lives in `features/libraries`, not `features/refManagers`.** `refManagers` is a reserved directory (README D1); the pin is a `pinnedPanels` entry of `libraries`, which this package owns. The `refManagers` stub can stay empty.
- **The Mendeley tab is always shown.** The plan hides Mendeley until `MENDELEY_CLIENT_ID` is set, but a plugin registers its panels synchronously, before capabilities load, and the owner asked for the tab on the main row. Unconfigured, the tab says sign-in isn't set up and names the alternatives (`mendeley-unconfigured`); on a server without WP35 it says the server can't link Mendeley yet (`mendeley-unsupported`).
- **"Update citations" is done in the browser.** WP35's frozen contract has no route for it, so the notice rewrites the open `.tex` file through `page.editDocument` (one undo step, only keys inside citation commands, comments skipped) and lists the other `.tex` files that still cite an old key (read with `GET /file`), each a button that opens it.
- **The Zotero tab keeps the V1 owner-only flow** through the `/api/zotero/*` aliases WP35 keeps; generic Zotero links made by other members are covered by the read-only rule and the renamed-key notice, but are not yet listed in the Zotero tab (see For later packages).

## Contract assumptions (for WP35 and the integrator)
The plan freezes routes, not bodies. The client reads tolerantly; these are the shapes it sends and accepts:
- `GET /api/libraries/:p/connection` → `{connected: boolean, name?|username?}`; 404 = this server cannot connect to `p`. `DELETE` disconnects.
- `GET /api/libraries/:p/connect?returnTo=<path+query, base included>` starts OAuth (top-level navigation; the desktop auth window takes it). The client adds `?libraries=<p>` to `returnTo` and, back on the page, selects that tab and removes the parameter.
- `GET /api/libraries/:p/libraries` → `[{id, name}]` (or `{libraries}`); `GET /api/libraries/:p/collections?library=<id>` → `[{id|key, name, parentId|parent?, path?}]` (or `{collections|folders}`).
- `GET /api/projects/:id/libraries` → the plan's array (or `{links}`); optional `linkedByName`. 404 = no generic links on this server (asked once per tab).
- `POST /api/projects/:id/libraries` with `{provider, branch, library, libraryName, collection?, collectionName?, recursive, bibFile, omitFields}` → the link (or `{link, jobId}`); with no `jobId` and no `lastSyncedAt` the client starts a sync itself.
- `POST …/:linkId/sync` with `{branch, olderThan?}` → `{jobId}`, or a finished result, or `{fresh: true}` when not stale. `GET …/jobs/:jobId` → `{state, itemCount?, renamedKeys?, error?}`; finished states `done|ok|finished|completed|succeeded|unchanged`, failed `error|failed|cancelled|paused`. `renamedKeys` may be `[{from,to}]`, `[[from,to]]` or `{from: to}`.
- Capabilities: `libraries.mendeley` (and `libraries.zoteroOAuth`), flat or as `libraries: {mendeley, zoteroOAuth}`.
- The legacy Zotero routes (`/api/zotero/*`, `/api/projects/:id/zotero/*`) keep their V1 bodies; a `renamedKeys` field on their sync replies is shown too.

## Privacy notes
No new hosts are contacted from the browser: every request goes to the Laytekz server. The Mendeley sign-in is a navigation to the server's `/api/libraries/mendeley/connect`, which redirects to Mendeley. Nothing new is stored in the browser; `libraries.syncOnOpen` is an account preference (a boolean). The link dialog tells the user that everyone in the project can read the synced file, and leaves out abstracts, files and annotations, and tags by default.

WP41 (desktop file links) needs nothing from it: the read-only rule re-reads the links on `filesChanged`, at most every 5 s.
- `plugins/zotero/library-panel.js` `registerLibraryPanel(aldine, cfg, util)` is provider-generic: a Zotero tab over the generic links (any member linking their own library, recursive collections) is the same call with `provider: 'zotero'` once the V1 owner flow is retired.
