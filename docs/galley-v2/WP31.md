# WP31 env-closing

## Summary
Feature 12's environment closing now has one closer. Typing the `}` of `\begin{itemize}`, pressing Enter at the end of a `\begin{…}` line, or choosing an environment from the completion list adds the matching `\end{itemize}` line, unless an `\end` is already waiting for it. Enter on an existing `\begin` line no longer adds a second `\end`.
- The `\end` block is an undo step of its own. One Undo removes only that block, and Backspace right after takes it back.
- Argument environments (`tabular`, `minipage`, `multicols` …) leave the caret in `\begin{tabular}{¦}`. Typing `}` steps over that brace, and Enter on the line moves into the body.
- Editing the name in `\begin{…}` or `\end{…}` renames its partner in the same transaction, and while the caret is in a name its partner is outlined (`data-testid="env-partner"`).
- After `\end{`, the completion list puts the innermost open environment first.
- Commands with several arguments (`\frac`, `\href`, `\multicolumn`, `\textcolor` …) complete with tab stops: Tab moves to the next pair of braces and then past the last one, Shift+Tab goes back, Escape leaves them.

Each part has a switch under Settings › Typing.

## Deviations
- **`envclose.close` is not marked `automatic`.** Version 1 always closed environments, and legacy spec 13 ("typing \begin{itemize} closes it once", in both its key and Option-layout variants) types against that with the automatic changes off. So the switch is on by default under `automatic-off` too. It is still a real off switch: turned off, none of the three paths adds an `\end`, and V1's brace handler stands aside as well. `envclose.linked` and `envclose.tabStops` are `automatic: true`. All three are account scope, section `typing`, default true. `close` and `linked` are `palette: true`.
- **`latexExtras.ts`, `completions.ts` and `newlineIndent.ts` are not edited.** WP19's uncommitted work is in `latexExtras.ts`, so I left it alone.
  - The plan's environment wrapper inside `latexPackageCompletions` and the `\end{` boost are the feature's `completionFilter` instead. It sees the package's environment options (type `class`) and the math-mode `\begin{equation}`-style commands, and replaces their apply.
  - The tab stops use the same filter. `MULTI_ARGUMENTS` (in `completion.ts`) copies the entries with two or more arguments from `latexExtras.ts` `ARGUMENTS` and `completions.ts` `EVERYDAY`. A new command with several arguments must be added there too.
- **Enter closing runs only in Source mode.** In Visual mode, Enter belongs to Visual's own keys (in V1, Visual's `Prec.high` Enter ran before the package's). The `}` closer and completions run in both modes.
- **Files.** The feature runs in `.tex`, `.ltx`, `.sty`, `.cls` and `.dtx` files. Elsewhere, and in an editor with no feature host, `closeBeginBrace` keeps V1's `}` closing, now without duplicates. Enter and environment completions no longer add `\end` there, because the package's auto-close is off everywhere.
- **The Enter path takes two steps.** The line break is an ordinary step, then the `\end` line is an automatic edit. One Undo after Enter removes the `\end` line and keeps the new line. Backspace right after does the same.
- **The "already closed" test** counts tokens, not just the first one. An `\end{name}` waits for the new `\begin{name}` when the unmatched `\end`s after it outnumber the environments still open before it, and the nearest of those `\end`s has the same name. So a nested `itemize` inside an `itemize` is closed, and a retyped `\begin{itemize}` above an orphaned `\end{itemize}` is not. Scans read at most 200,000 characters each way and skip comments, `\verb` and raw environments (`verbatim`, `Verbatim`, `lstlisting`, `minted`, `comment`, `filecontents`).
- **Linked rename** mirrors only local `input.*` and `delete.*` transactions with exactly one change, made inside one name, when both names were equal before the edit and the inserted text has no brace, backslash, `%` or whitespace. Composition, several cursors, remote changes, undo and redo are never mirrored. Accepting a name from the list inside an existing pair replaces the whole old name, so its partner follows. The outline is drawn only when the two names are equal.
- **No notice** is shown for a closed environment (V1 closed silently; a notice would repeat on every environment).
- **Not built:** a "close the current environment" command (the analyst's gap list mentions it, but the plan's WP31 brief does not).

## For later packages
- **Tab (WP40 inline suggestions):** while snippet fields are active, `envclose.nextField` takes Tab at 90 (`KEY_CHAIN_PRIORITY.Tab.fields`). Shift-Tab is also taken at 90, and Escape at 95. Check `hasNextSnippetField(state)` from `@codemirror/autocomplete` before showing or accepting a suggestion.
- **Enter:** `envclose.argJump` sits at Enter 90 and acts only on a just-closed argument environment's `\begin` line. `envclose.enterClose` sits at 89. Both stay out of the way while a completion list is active.
- **Closing from code:** call `planEnvClose(state, pos, { args: true })` from `editor/beginEnv.ts` with `pos` right after `\begin{name}`. Dispatch the result with `applyExplicitEdit` and `autoEditMark.of('envclose.close')`, as `closeAfterCompletion` in `features/envclose/close.ts` does. A snippet that inserts its own `\end` needs neither.
- **Scans:** `envScan`, `envNameAt`, `envPartner` and `innermostOpenEnv` in `editor/beginEnv.ts` pair environments by position, skipping comments and raw text.
- **A command with several arguments** belongs in `MULTI_ARGUMENTS` (`features/envclose/completion.ts`) to get tab stops.
