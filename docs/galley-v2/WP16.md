# WP16 reference-lookup

## Summary
The server half of feature 9 (online BibTeX) now exists. One query box can be
answered for a DOI, an arXiv ID (new or old style), a PubMed ID or PMCID, an
ISBN, an OpenAlex ID, pasted BibTeX (the Google Scholar path), a pasted
formatted citation, or a title, searched across OpenAlex and Crossref (PubMed
for "Medicine", DataCite for "Datasets", Semantic Scholar when keyed) and
merged into one result per paper. A preview shows the exact entry the project
would get (project key style, capitals protected, field names for the paper's
package) and whether the paper is already there; insert appends it and returns
a hash that remove uses to take it back. V1's add route and MCP
`references_add` get the key-collision fix and the UTF-8 guard. The panel UI is
WP22's; until it lands, users see the fixes through the V1 Cite panel.

## Marked hunks
**`apps/server/src/references.ts`** (upstream file, rewritten as the
orchestrator): `// Galley: V2 (WP16) the lookup engine lives in refs/; this file
orchestrates it and keeps V1's exports.` above the new imports. The text
cleaning, parsing and layout helpers moved verbatim to `refs/bibtex.ts`, the
DOI resolver and `doiHopAllowed` to `refs/sources/doi.ts` (re-exported), the
Atom parser to `refs/sources/arxiv.ts`. Behaviour changes in the V1 entry
points:
- `fetchBibEntry` (MCP, `/references/add`): an arXiv ID is fetched through
  doi.org's `10.48550/arXiv.<id>` (DataCite: first version's year and a DOI)
  before the Atom feed; OpenAlex requests no longer send `mailto`.
- `searchWorks` (`/api/references/search`): searches Crossref instead while
  OpenAlex's daily budget is under 10% or spent (hit ids `crossref1…`; every
  hit has a DOI, which the V1 plugin adds by).
- `addReference`: the same paper is recognised by identifiers (DOI, arXiv,
  PMID, ISBN) or a near-identical title with year within one and the same
  first-author surname; a key another paper holds gets a suffix
  (`smith2020a`) instead of being reported as a duplicate and citing the wrong
  paper. A target that is not UTF-8 is refused with its bytes untouched.

**`e2e/tests/mocks/refs.mjs`**: `// Galley: V2 (WP16) arXiv through doi.org's

## Routes (all in `features/references/server.ts`)
| Route | Who | Body / query | Answer |
|---|---|---|---|
| `GET /api/references/lookup` | signed in (401 otherwise when accounts are on) | `q`, `filter` = `all`\|`medicine`\|`datasets` | `{kind, results: Candidate[], errors: [{source, message}], notice?, scholarUrl?}` |
| `GET /api/projects/:id/references/lookup` | anyone who can open the project, signed in | `q`, `filter`, `branch` | the same, each result with `inProject: {key, bibFile}` when the branch already has the paper |
| `GET /api/projects/:id/references/targets` | anyone who can open the project | `branch` | `{targets: [{path, exists, loaded, synced, editable}], default, format, rootFile}` |
| `POST /api/projects/:id/references/preview` | members | `{branch, id?, bibtex?, key?, bibFile?}` | `{bibtex, key, keyNote?, duplicate: {key, bibFile}\|null, bibFile, loaded, targets, format}`; writes nothing |
| `POST /api/projects/:id/references/insert` | members and tokens | `{branch, bibtex, key?, bibFile?, loadBib?, force?}` | `{ok, key, bibFile, duplicate, created, entryHash, keyNote?, loaded, loadAdded?}` |
| `POST /api/projects/:id/references/remove` | members | `{branch, bibFile, entryHash}` | `{ok, removed}`; 409 `code:'changed'` when the entry's text changed |

- `Candidate`: `{id, source, sources?, title, authors[], year, venue, type?,
  doi?, arxiv?, pmid?, isbn?, openalex?, score?, weak?, preprint?,
  publishedDoi?, bibtex?, rank}`. The client previews a result by sending its
  `id` (`doi:…`, `arxiv:…`, `pmid:…`, `pmcid:…`, `isbn:…`, `openalex:W…`), or
  its `bibtex` for pasted BibTeX (the pasted key is kept unless it collides).
- Errors carry `{error, code}` with code `not-utf8` (409, the sentence "This
  .bib isn't UTF-8, so adding to it would damage it. Choose another file."),
  `synced` (409, the Zotero file), `bad-bibtex`, `bad-key`, `bad-path`,
  `not-found` (404), `changed` (409). An upstream failure is 502 with a
  sentence; `REFERENCES_ONLINE=0` makes lookups and online previews 404.
- A duplicate insert writes nothing and answers `duplicate: true` with the
  existing key and file ("Cite smith2020"); `force: true` is "Add anyway"
  (the entry gets a free key).
- An open `.bib` is appended to (and removed from) through its live Yjs doc,
  so the edit merges with typing; a closed one is written on disk, line
  endings kept. `loadBib: true` runs bibload's `addBibLoad` when the paper
  does not load the file.
- `tokenWrites`: `POST /api/projects/:id/references/insert`, because an
  agent with a token already adds references through MCP `references_add`;
  the REST insert takes the same final BibTeX and goes through the same
  checks. Remove and preview stay closed to tokens; nothing is open to viewers.

## Project settings (`ProjectMeta.ext`, client-visible and writable, copied by "Make a copy")
- `references.keyStyle`: `authoryear` (default, `vaswani2017`), `scholar`
  (`vaswani2017attention`), `bbt` (`vaswaniAttentionAllYou2017`).
- `references.protectCaps`: boolean, default on (absent = on).
- `references.fieldStyle`: `auto` (default: follow the paper), `biblatex`, `bibtex`.
- `references.defaultBib`: a `.bib` path, or `''` / absent for automatic.

The client `SettingDef`s for these (scope `project`) and the per-user
settings of plan §1.1 ("Look up references online", "Preview before
adding", "Cite at cursor", "Search online in \cite completion") are WP22's.

## Deviations
1. **No `refs/routes.ts`.** The ownership matrix gives WP16 the feature
   module, so the routes are registered by `features/references/server.ts`
   through the feature host; `routes.ts` needed no edit.
2. **Insert route name.** The plan's `…/references/insert` is a new route;
   V1's `/references/add` keeps its body and answer.
3. **PubMed without a DOI** uses ESummary's fields (title, authors, journal,
   volume, issue, pages, date) instead of NCBI's CSL exporter: one host,
   one pacer, the same entry.
4. **arXiv "Published version available"** comes from the OpenAlex work's
   locations (`publishedDoi`), only for single arXiv lookups, not for every
   search result.
5. **`markInProject`** compares against every `.bib` on the branch (as
   `/bib` does), not only the loaded ones.

## Privacy notes
- Hosts contacted, only when a signed-in user looks something up (or an
  agent calls `references_add`): doi.org (and the agencies it redirects to:
  Crossref, DataCite, mEDRA, JaLC), api.crossref.org, api.openalex.org,
  export.arxiv.org, eutils.ncbi.nlm.nih.gov, api.datacite.org,
  openlibrary.org, and api.semanticscholar.org only when `S2_API_KEY` is set.
  The server never contacts Google Scholar; `scholarUrl` is a link the user's
  own browser opens.
- What they receive: the query text or identifier, the server's IP address,
  and the User-Agent `Laytekz/<version>` (no URL, no address). With no
  operator variables, no request carries an email address, a `mailto` or
  `email` parameter, or any key (tested). `REFERENCES_CONTACT_EMAIL`, when
  the operator sets it, goes only to Crossref (in the User-Agent), NCBI
  (`email=`) and DataCite (`mailto=`); `OPENALEX_API_KEY` only to OpenAlex;
  `NCBI_API_KEY` only to NCBI; `S2_API_KEY` only to Semantic Scholar.
- Stored: nothing new on disk. An in-memory cache keeps identifier → BibTeX
  for 24 h and query → results for 10 minutes (pasted BibTeX is never
  cached). Appended entries land in the project's `.bib`, visible to every
  collaborator, as in V1.

## Operator variables
All optional; none set means public limits and nothing personal sent.
| Variable | Default | Effect |
|---|---|---|
| `REFERENCES_ONLINE` | on | `0` turns online lookup off (lookup and online preview answer 404; insert of given BibTeX still works) |
| `REFERENCES_CONTACT_EMAIL` | unset | The operator's own address for Crossref's polite pool, NCBI and DataCite |
| `OPENALEX_API_KEY` | unset | Strongly recommended (free): about 1,000 searches a day instead of about 100 |
| `NCBI_API_KEY` | unset | NCBI 10 requests/s instead of 3 |
| `S2_API_KEY` | unset | Turns Semantic Scholar search on |
| `REFERENCES_SOURCES` | all | Comma list restricting the sources (`crossref,openalex,arxiv,pubmed,datacite,openlibrary,semanticscholar`) |
| `CROSSREF_API_BASE`, `DATACITE_API_BASE`, `PUBMED_API_BASE`, `OPENLIBRARY_API_BASE`, `S2_API_BASE` | the public services | Test mocks only (as the existing `DOI_API_BASE`, `ARXIV_API_BASE`, `OPENALEX_API_BASE`) |

Pacing, server-wide: Crossref lists 1/s (3/s with a contact), single records
5/s; arXiv one request per 3 s; NCBI 3/s (10/s keyed); OpenAlex 10/s (30/s
keyed). A 429 with Retry-After up to 5 s is waited out once; a longer one
reports that source busy. Each source has a 4 s budget per search and failing
sources come back in `errors[]` beside the others' results.
