# WP02 settings-core

## Summary
The settings store now exists: every setting's effective value, whatever its
scope (device, account, project), behind `getSetting`/`setSetting`/
`subscribeSetting`/`useSetting`, with the twelve V1 preferences on their V1
keys and exact V1 codecs, account sync (three-way merge, offline queue, ETag
polling), project settings, the capabilities client, `openSettings`, the
appearance "apply" layer (theme, interface size, contrast, motion, PDF in the
dark theme, editor typography), the pre-paint additions and their CSS, and
`theme.ts` moved onto the store. For a user nothing changes yet: every new
setting defaults to what V1 shows, `main.tsx` still calls `startThemeSync()`
(device layer and apply only), and account sync starts only when the page host
(WP06) calls `startSettings()` and the server (WP03) reports `prefs: true`.

## Requests

### R1: apps/web/src/util/shortcuts.ts and apps/web/src/keys/registry.ts (WP04): write chords through the store
- **Anchor:** `util/shortcuts.ts` `setChord`, the line `safeStorage.setJSON(STORE, next);`
  (or its successor in `keys/registry.ts`), and the module-level
  `window.addEventListener('storage', …)` for `aldine.shortcuts`.
- **Hunk** (sketch):
  ```diff
  +  // Galley: V2, the store keeps aldine.shortcuts and the account in step (WP02)
  +  setSetting(CORE_SETTING_IDS.shortcuts, next);
  -  safeStorage.setJSON(STORE, next);
  ```
  and read with `getSetting(CORE_SETTING_IDS.shortcuts)` /
  `subscribeSetting(CORE_SETTING_IDS.shortcuts, …)` instead of a second
  `storage` listener.
- **Why:** `keys.shortcuts` is an account setting on the V1 key. A direct
  `localStorage` write is read correctly by the store (it compares the stored
  text on every read) but is never sent to the account and notifies nobody in
  the writing tab.
- **Without it:** shortcuts keep working per browser exactly as in V1; they
  just do not follow the account.

### R2: apps/web/src/components/CodePane.tsx or editor/core/editorSettings.ts (WP05): re-measure after a typography change
- **Anchor:** where the editor-settings compartment subscribes to its settings.
- **Hunk** (sketch, at most a few lines):
  ```diff
  +  // Galley: V2, the font, size and line height are CSS variables (WP02 apply.ts): CodeMirror must measure again
  +  useEffect(() => subscribeSetting(['editor.font', 'editor.fontSize', 'editor.lineHeight', 'editor.ligatures', 'appearance.scale', 'visual.fontSize', 'visual.width'],
  +    () => requestAnimationFrame(() => viewRef.current?.requestMeasure())), []);
  ```
- **Why:** the typography settings change CSS variables on `<html>`, which
  CodeMirror does not notice; without a re-measure the cursor and line
  heights stay at the old size until the next scroll or resize.
- **Without it:** the text changes size at once; cursor placement catches up
  on the next scroll or window resize.

### R3: apps/server/src/privacy.ts (integrator): settings sync
- **Anchor:** the "What is stored" list.
- **Hunk:** "Your settings (theme, editor font and size, typing aids,

- **Why:** account-scope settings are stored on the server once WP03's

## Deviations
- **Extra exports** (additive; no contract signature changed):
  - `settings/store.ts`: `startLocalSettings()`, `defaultOf(def)`,
    `memoryBacked(base)`, `getSyncStatus()`, `subscribeSyncStatus(fn)`,
    `useSyncStatus()`, `onSettingsConflict(fn)`, `syncSettingsNow()`,
    `__settingsTestHooks()` (tests only), and the types `SyncStatus`,
    `SettingsConflict`.
  - `settings/capabilities.ts`: `subscribeCapabilities(fn)`,
    `normaliseCapabilities(raw)`.
  - `util/desktop.ts`: `parseDesktopVersion(userAgent)`.
  - `api.ts`: `sessionUser()`, `onSessionUser(fn)`.
  - `util/useMediaQuery.ts`: `useReducedMotion()`.
  - New modules: `settings/codecs.ts`, `settings/sync.ts`,
    `settings/apply.ts`, `settings/url.ts` (`settingsPath`,
    `parseSettingsPath`, `isSectionId`), `settings/registry/core.ts` also
    exports `CORE_EXTRA_IDS`, `UI_SCALES`, `EDITOR_FONTS`,
    `SPELL_LANG_OPTIONS`, `isFontName`.
- **V1 keys are written in V1's texts, defaults included** (`'0'`/`'1'`,
  `'system'`, `String(zoom)`, `'{}'`): the analyst report's "removing the key
  at the default" would have broken the raw-storage assertions of specs 27, 52
  and 54 once WP06 moves the toggles onto the store. JSON-coded new settings
  do drop their key at the default; `resetSetting` removes either.
- **`layout.panes` is `'' | 'editor' | 'both' | 'pdf'`**, '' meaning "the
  window's width decides" (V1's `readLayout()` null): a `Control` option value
  cannot be null. `''` removes the key, as V1 never wrote it.
- **`keys.shortcuts` is `Record<string, Chord | null>`** (null: a binding the
  person unbound, for WP23's "None"); its codec keeps every well-formed entry
  of any id (V1's reader only looked at its five ids; it still does).
- **Five editor variables, not four:** `--editor-font-size` joins the plan's
  `--editor-font`, `--editor-line-height`, `--visual-font-size`,
  `--visual-width` (the report put the size on `--text-code`; a design token
  is better left alone). A chosen size is in px (absolute); the default stays
  `--text-code` (rem, so it follows the interface size).
- **New settings' device keys are `aldine.<id>` with JSON text** (the
  contract's default), not the report's `aldine.uiScale`-style names; the
  pre-paint therefore parses JSON.
- **Interface sizes are 90/100/110/125%** (the report had 112%).
- **Sync switch:** the device setting `account.sync` (key
  `aldine.account.sync`, default on, visible only signed in with accounts);
  the sync's own keys are `aldine.settingsOwner`, `aldine.settingsBase`,
  `aldine.settingsPending`, `aldine.settingsBackup`.
- **Merge model:** a three-way merge against the last agreed state (see
  `settings/sync.ts`) instead of re-seeding with `keepExisting` on every load.
  It keeps the plan's rules (the first sync seeds with `keepExisting`; the
  account wins a conflict, with the device's value kept for "Keep this
  browser's"; another account never seeds) and adds two: a reset made on
  another device is never resurrected, and a change made here while signed
  out is sent at the next sign-in if the account has not moved.
- **`setSetting` on a project-scope id** sends the project PATCH (logging a
  failure) instead of doing nothing; pages should still use
  `useProjectSetting`'s setter, which reports failures.
- **`refreshProjectSettings()` never rejects** and asks the server nothing
  while no project-scope setting is registered (none is in wave 0).
- **Account sync starts only with `startSettings()`**; `theme.ts`'s
  `startThemeSync()` (what `main.tsx` calls today) starts the storage listener
  and apply only, so nothing reaches the server before WP06 switches
  `main.tsx` to `startSettings()`.
- **Hidden rows:** `editor.mode`, `pdf.zoom` and `keys.shortcuts` are
  `visible: () => false` (toolbar state, and the Shortcuts section's own
  rows). The five V1 toggles with palette commands (`vim`, `spell`, `auto`,
  `draft-typeset`, `change-marks`) are `palette: false` so
  `settingToggleCommands` cannot duplicate them.
- **z-index tokens** are defined with today's values; existing literal
  `z-index` declarations are left as they are (no visual change).
- The `--auto-edit-flash` colour is the accent at 18% (light) / 24% (dark).

## Privacy notes
- Account-scope settings (theme, interface size, contrast, motion, editor
  font/size/line height/ligatures, Visual size and width, spellcheck and its
  language, Vim, change marks, the editor menu, explain notices, auto-typeset,
  quick draft, PDF in the dark theme, shortcuts) go to the instance's own
  server only: `GET/PATCH /api/account/preferences` (WP03), signed in, with
  the switch on. Nothing goes to any other host.
- localStorage (this browser): each setting's key (`aldine.<id>` or its V1
  key), plus `aldine.settingsOwner` (the id of the account that last synced
  here), `aldine.settingsBase` (that account's last agreed values),
  `aldine.settingsPending` (changes not yet sent), `aldine.settingsBackup`
  (values the account replaced, for "Keep this browser's").
- `GET /api/capabilities` once per tab and after a sign-in or sign-out.
- `util/desktop.ts` reads the user agent's ` Laytekz-Desktop/<v>` token; it
  identifies the app and is never trusted for anything.

## For later packages
- Read and watch: `getSetting<T>(id)`, `subscribeSetting(ids, fn)`,
  `useSetting<T>(id)`; change: `setSetting(id, v)`, `resetSetting(id)`.
  Project values: `useProjectSetting<T>(id)` → `[value, set, { canEdit }]`.
- `getSetting` is cheap (one `localStorage` read, decode only when the text
  changed) and safe per keystroke; it returns the same object until the stored
  text changes.
- Define a feature's settings in `features/<id>/settings.ts` as pure data
  (ids `<featureId>.<name>`; account ids must match `PREF_KEY_RE`; set
  `automatic: true` on anything that changes what the person typed).
- Write a device key only through `setSetting`: a direct write is read
  correctly but neither syncs nor notifies the writing tab.
- `openSettings({ section, setting })` dispatches `laytekz:open-settings`;
  build in-app links with `settingsPath(target, projectId)` and parse routes
  with `parseSettingsPath(pathname, hash)` (`settings/url.ts`).
- WP06: switch `main.tsx` from `startThemeSync()` to `startSettings()`; call
  `setSettingsProject({projectId, canEdit})` / `setSettingsProject(null)`; on
  the `settings` branch signal call `refreshProjectSettings()` and emit
  `projectSettingsChanged` with its result.
- WP23: `useSyncStatus()` ('local' | 'saving' | 'saved' | 'offline' |
  'error'), `onSettingsConflict(c => toast(..., { label: "Keep this browser's", run: c.keepBrowser }))`,
  `syncSettingsNow()`.
